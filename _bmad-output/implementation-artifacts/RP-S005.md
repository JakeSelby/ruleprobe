## Story

As any builder of ruleprobe 0.2, human or agent, I want an architecture spine that fixes the
invariants two independently built units could get wrong, so that a reader, a matcher, the
report and a downstream consumer stay compatible without reading each other's code.

## Context and value

The code already had a shape, but it was written down nowhere except module docstrings. 0.2
changes the contract that agent-harness vendors, adds opportunity counts to rows, and adds a third
reader. Each of those is a place where two builders can diverge. The PRD says what; the spine
fixes how, only where a wrong guess breaks something.

## Acceptance criteria

1. **Given** the code and the PRD, **when** `bmad-architecture` runs brownfield, **then** the spine
   names the paradigm the code shows and ratifies its conventions rather than inventing new ones.
2. **Given** each AD, **when** it is read, **then** it binds real FR ids, and each `[ADOPTED]`
   claim matches the code.
3. **Given** agent-harness's AD-13 and AD-21, **when** the spine is read, **then** both are listed
   as inherited, read-only, and no local AD weakens them.
4. **Given** a fresh-context validation with an adversarial lens, **when** it reports findings,
   **then** each is applied through the update intent and logged.
5. **Given** a spine change that makes the PRD stale, **when** it lands, **then** the PRD is
   amended in the same pull request.
6. **Given** `lint_spine.py`, **when** it runs on the final spine, **then** it reports no findings.

## Design

### Approach

Headless Fast path, brownfield: every module docstring, the corpus labels, the shipped detector
file and the equivalence test were read before any decision. Then an independent validation,
an update, and the configured polish lenses, each in its own context.

### Decisions and alternatives

- **Pipes and filters, batch per session.** Confirmed from the code with one correction to the
  brief: sessions stream, but a session's events are materialised whole, because the session
  matchers read the whole list.
- **An over-count found by reading the code.** A matcher over a Bash command the parse skipped
  returns false, so `not` and `absent` fire. The validation reproduced it and found `git`
  affected too; it is filed as #19 (RP-B001) and AD-4 makes "undecided" the rule for 0.2.
- **Compliance polarity from the code.** The first draft took "followed" for `absent` from the
  PRD glossary, which had the polarity backwards against `matchers.py`; rates would have come
  out inverted. AD-11 now takes it from the code, and the PRD glossary was corrected.
- **Undecided is its own count.** An opportunity whose outcome cannot be read is never recorded
  as not followed.
- **Package data as Python literals.** The persisted fold map and shipped-id list load from a zip
  on Python 3.9 with no file reads, because agent-harness imports the wheel from a zip in a hook.
- **The independent review is the validation.** The author's in-context lens passes are kept in
  `reviews/` as working notes; the gate's independent review is `validation-report.md`.

### Do not implement

- The fix for #19; it has its own issue in 0.2.0.
- The deferred product calls: the third runtime, the section split unit, the catalog size, the
  drafting command, and the schema version value.
