## Story

As a first-time user,
I want my own rules bound to shipped detectors by what they say,
so that I get a measured answer without writing a detector.

## Context and value

This is the step that closes the sixty-second gap without a model (maintainer decision 7). Today a
rule is measured only when its file's front matter carries a `detector:` block (`read_rule_file` in
`ruleprobe/rules.py`); nothing binds by rule text. FR-16 ships declarative detectors for common rule
shapes and binds each section rule (RP-S015) to at most one of them. The shapes are fixed by RP-D009.
SM-1's counter, catalog precision, is why every entry must clear the corpus floor.

## Acceptance criteria

1. **Given** each catalog entry, **when** CI runs `ruleprobe corpus --floor 0.9`, **then** it carries
   `examples:` and scores at or above the floor.
2. **Given** a named fixture rule file whose sections each follow one catalog shape, **when**
   `report --rules` runs, **then** each section binds that entry and is reported measured and
   catalog-bound.
3. **Given** a rule whose text matches no entry's anchored pattern, or more than one, **when** bound,
   **then** it stays unmeasured.
4. **Given** a user detector with a catalog id, **when** the bundle builds, **then** the rule is
   reported bound to the user's own (AD-12 precedence), and `DEFAULT` is unchanged (AD-14).
5. **Given** the catalog loaded from a wheel on `sys.path` as a zip, **when** a bundle builds, **then**
   it loads with no file read beside `__file__`, and a test asserts `ruleprobe/detectors/catalog.py`
   holds only literals. Entries are Python literals in that module, compiled with `compile_detector`.
6. **Given** each catalog id, **when** the shipped-id test runs, **then** it is on the shipped-id list.
7. **Given** binding, **when** it runs, **then** it reads rule text with no model.

## Design

### Approach

Add `ruleprobe/detectors/catalog.py`: a module of Python literals, one entry per RP-D009 shape, each
with a declarative detector spec, `examples:`, and one anchored text pattern (AD-9, AD-7). `rules`
imports it; it imports only `matchers` and compiles entries with `compile_detector` (AD-1).
[Superseded by decision 7: `detectors.catalog` imports nothing and `rules` compiles it.] In
`rules.py`, bind each unbound section rule by testing its text against every entry's pattern; exactly
one match binds with source `catalog`, none or several leave it unmeasured (AD-12, NFR-4). Registry
order is shipped, then catalog, then discovery, built from `DEFAULT.copy()` (AD-12, AD-14); a user id
that replaces a catalog id wins and the rule reports as the user's own. [Superseded in part by
decision 2 - a catalog detector joins only when a rule binds it - and decision 3 - an entry
restating a shipped id leaves the shipped detector in place.] Catalog ids join the shipped-id
list in `ruleprobe/contract_data.py` (from RP-S009). [ASSUMPTION: `contract_data.py` is created by an
earlier Epic 1 story; it does not exist today]

### Decisions and alternatives

- One anchored pattern per entry, exact-one match; a model-based binder is out of scope (FR-16, NFR-7).
- Literal module over a YAML package-data file, so the zip import needs no file read (AD-9 as amended
  2026-09-23).

### Build-time decisions

Each is a default taken where the design was silent, headlined for confirm or override.

1. **A section id with a slash binds on the rule entry, never on `Detector.rule`.** The catalog
   detector keeps its own slash-free `rule`; the section's `RuleEntry` lists the detector id and
   records `source`. `Registry.add` and the naming convention are unchanged, and a rule file in a
   subdirectory binds as one at the root does.
2. **A catalog detector joins a report's registry only when a rule binds it**; `ruleprobe corpus`
   adds every entry (`Bundle.registry(whole_catalog=True)`), so CI's floor scores the whole
   catalog while a report with nothing bound is unchanged.
3. **Shapes 2 and 5 reuse the shipped ids** `verification/no-verify` and
   `transcript-hygiene/whole-file-cat` with their `common.yaml` twins, so a report never carries two
   lines for one observable. A catalog entry whose id the base registry already holds leaves that
   detector in place; a user's detector still replaces either.
4. **Shape 4 ships as uv over pip** (`package-manager/pip-install`): one anchored pattern cannot
   carry a parameter, so the entry names one pair.
5. **Patterns match at the start of a sentence.** The heading and each sentence of the section's
   prose (list items, links, code and emphasis markers read through) are tested with
   `re.match`, case-insensitive.
6. **The coverage block notes a binding** as `catalog-bound, <id>`, and a rule matching several
   entries is unmeasured with the reason `matches N catalog entries: ...`.
7. **`detectors.catalog` imports nothing**; `rules` compiles its entries, so the literals-only test
   holds and the spine's AD-1 edge to `matchers` is dropped by amendment.
8. **Review round 1:** shape 1 is the `order` detector `testing/test-after-change` (a Write or Edit
   followed by a test run, so a hit is a followed opportunity); bound catalog detectors lead
   `Bundle.detectors`, `DEFAULT` ids excepted; a catalog id held by a plugin, `base` or a loaded
   detector is `own`; an id the fold map retires never binds; a heading-less file, or a headed one
   with no rule section, binds by its whole text; `coverage` carries a `catalog` count;
   `ruleprobe detectors` lists every entry marked `catalog`; `corpus` adds a restating entry's
   examples to the shipped row.
   The detectors listing, the coverage `catalog` key, whole-text binding, the retired-id
   skip, and the prepend and relabel are this decision's; `_score_restated` is this
   decision's and decision 12's.
9. **Catalog detectors read Bash through the shared parse only (review round 2).** The
   hand-written command-position prefix backtracked exponentially, so every entry now uses
   `command`, `git` and `env` keys, per segment and per argument (AD-5). Two shapes needed a
   regular expression the parse could not replace - a secret-shaped path, and a commit
   subject - so the `git` matcher gains `arg_regex`, searched in one parsed argument, and
   `message_regex`, searched in the call's first `-m`/`--message` value, with a message
   holding a variable, a substitution or a heredoc undecided. This widens the AD-7
   vocabulary. The test runners are listed by name and wrapper; one behind an assignment or
   a flag (`CI=1 pytest`, `mvn -q test`), under another path or through another wrapper is a
   stated under-count, and so are a force-push cluster not opening with `f`, a
   `feature:main` refspec, and a `WIP:` subject. [Corrected in round 3: memoising `then`
   per event, as first written here, still walked every opened event's window, so `order`
   stayed O(opened x window); decision 15 makes it linear.]
10. **A binding pattern never spans a clause break, and an exception binds nothing (review
    round 2).** Patterns use a run of characters that stops at `;`, `,`, `:`, ` - ` or a
    dash, never `.*`; the one comma one may cross opens its own contrast ("use uv, not
    pip"), so the fixture's phrasing still binds. A sentence carrying except, unless, other
    than, but, however, allowed, fine, okay or ok binds nothing, so "Never force-push except
    to main" and "Use uv for scripts, not poetry; pip is fine" stay unmeasured. An
    under-count: "Force-pushing main is not allowed" binds nothing either.
11. **`Bundle.registry` labels from the loaded binding on every call (review round 2).** It
    never mutates the binding: `rules` reads as `load_bundle` bound it until the first
    call, then as the latest call labels it, recomputed from the binding each time. A
    catalog id the base registry's effective fold map retires is neither added nor bound,
    and a catalog-bound rule whose id the registry does not hold is unmeasured with a
    reason. Binding itself still runs at load against the shipped fold map, so a rule that
    matched two entries, one retired by the base, stays unmeasured rather than rebinding.
12. **`report --validity` and `corpus` score a restated shipped detector alike (review
    round 2).** Both apply `_score_restated`; a row the corpus did not score is the
    examples' score alone and its `source` says `examples`; a shipped id a plugin or a
    detector file replaced takes no catalog examples.
13. **The README's "Sixty seconds on a rule of your own" opens with the catalog (review
    round 2).** The heading already existed on `main` for a detector written as data; the
    catalog paragraph now opens it, with the fixture command, and the section says plainly
    that `testing/test-after-change` counts compliance while every other row counts
    violations.
14. **The catalog's tests sit in new files.** `tests/test_catalog.py`,
    `tests/test_git_arg_matchers.py`, `tests/test_command_program.py` and
    `tests/test_order_linear.py` rather than the files the Testing section names, which
    parallel stories may edit, so the change merges rather than conflicts.
15. **`order` is linear in the session (review round 3).** One pass evaluates `first`, one
    evaluates `then`, and a reverse pass gives each index the next true and the next
    undecided `then`; the window end comes from the positions of the non-`tool_result`
    events. Undecided handling, the `tool_result` distance rule and the opportunity triples
    are unchanged, which a differential test against the old walk proves over 400
    generated sessions.
16. **A rule carrying an exception or a condition anywhere binds nothing (review round
    3).** Any sentence, heading included, holding except (excepted, exception), unless,
    other than, apart from, excluding, without, but, however, allowed, fine, okay, ok, if
    or when leaves the rule unmeasured with the reason naming the word. Left out: `only`,
    which intensifies as often as it narrows ("use only uv"), and `instead` and `rather
    than`, which the pip shape uses. ` -- ` joins ` - ` as a clause break. The catalog
    fixture's "When a hook fails, fix what it found" became "Fix what a failing hook found."
    so that section still binds.
17. **Whole-text binding stays, and its over-count is stated (review round 3).** AD-12 binds
    a heading-less or rule-less file by its whole text; README says one matching sentence
    marks such a file measured, a known over-count of the measured share.
18. **`Bundle.registry` survives in-place edits (review round 3).** A rule list changed after
    a call is read with the entries that call labelled put back as they were bound, and a
    catalog detector no rule binds any more does not join. `catalog_detectors` joins
    `rules.__all__`, not the README's declared API.
19. **The command matcher gains `program` and `first_operand` (review round 3).** The
    runner and pip entries read a program by basename past `NAME=value` and the first
    operand past flags (`/usr/local/bin/pytest`, `CI=1 pytest`, `mvn -q test`,
    `.venv/bin/pip3.12 -q install`). Like decision 9's keys, this widens the AD-7 vocabulary
    and is pending Jake.
20. **Codex file edits open test-after-change opportunities (review round 3).** The Codex
    reader passes `apply_patch` through by name, so it joins Write, Edit and MultiEdit in
    `first`.
21. **Commit subjects (review round 3).** The valueless short flags are `a e i n o p q s v
    z`; `-amtext` reads `text`; `fixup! `, `squash! ` and `amend! ` are passed over; a `$`
    anywhere, single-quoted included, leaves the message unread because the parse keeps no
    quoting (stated under-count); the heredoc marker comes from `shell.MARKER_RE`.
22. **Push and secrets scope (review round 3).** `--force-if-includes` alone is no force
    push; the secrets entry and README say "Never commit secrets" is measured only by
    secret-shaped adds.

### Do not implement

- Any model call, or a command that drafts detectors from prose (FR-34).
- Catalog shapes beyond RP-D009's list.
- Changes to `DEFAULT` or `ruleprobe/detectors/common.yaml`.

## Review findings

Review round 2 (blind hunter, edge-case hunter, acceptance auditor, verification gap), each
with its resolution:

- **Blocker - the command-position prefix backtracked exponentially** (12 segments took 9.2 s
  on the old test-after-change regex). Fixed: decision 9; `HostileInputTests` runs every
  catalog regex and detector over hostile inputs under 0.5 s each.
- **force-push-default missed `refs/heads/main`, `HEAD:refs/heads/main`, `main:main`,
  `+refs/heads/main` and the master forms.** Fixed: listed in `args_any`; near-miss
  `feature:main-backup`.
- **`git add certs/public-key.pem` counted as a secret.** Fixed: a `.pem` naming `pub` is
  excluded; near-miss test.
- **A quoted ` -m ` in another option gave a false subject; `-sm` unread; `WIP:` passes.**
  Fixed: the subject is read from the parsed arguments (`message_regex`), `-sm` and `-asm`
  are read, and `WIP:` is a stated under-count in the description.
- **A consumer's fold map was ignored.** Fixed: decision 11; `catalog_detectors(fold)`, the
  registry and the CLI notes use the registry's effective fold map.
- **`Bundle.registry` relabelled `self.rules` one way.** Fixed: decision 11; test plugin
  base, then `DEFAULT`, then plugin base.
- **A catalog-bound rule whose id the registry lacks read measured.** Fixed: decision 11.
- **`report --validity` skipped `_score_restated`.** Fixed: decision 12; a test forces a
  failing example and asserts both commands print one score.
- **An examples-only restated row said `source: corpus`.** Fixed: decision 12.
- **No test for an override under a catalog id in `detectors` or `corpus`.** Fixed: two
  tests.
- **Binding was too loose (`.*`).** Fixed: decision 10, with both sentences as near-misses.
- **The zip probe could not fail.** Fixed: every package file, data included, is zipped,
  and the probe records reads through the loader (`get_data`, `get_resource_reader`) as
  well as opens under the archive. Proven: a `pkgutil.get_data` of `common.yaml` in the
  load path failed the test, and so did an `open` beside `catalog.__file__`; both reverted.
- **README and `read_rule_file` said a heading-less file stays unmeasured; no
  `detectors/catalog.py` in the layout; no section titled as the task says.** Fixed:
  decision 13 and the docstrings.
- **test-after-change counts compliance, unlike every other row.** Fixed: said in its
  description and the README.
- **The secret-file description omitted `.env.prod`.** Fixed.
- **Decisions numbered out of order; auditor's done-but-not-asked items.** Fixed: renumbered
  1 to 14 in order, and each item points at decision 8, 11, 12 or 14.
- **No `## Unreleased` changelog entry.** Open: the changelog is the orchestrator's.
- **AC 1 in CI.** The corpus gate runs `ruleprobe corpus --no-config --floor 0.9`, which
  scores every catalog entry (`whole_catalog`); the gate run for this round shows it.
