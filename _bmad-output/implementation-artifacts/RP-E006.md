# RP-E006 — Epic 4: Every hit explains itself, and a wrong hit becomes a label

- **Primary parent:** None
- **State:** active

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Goal

A developer can see the event and detector behind any hit, and can turn a false positive into a
labelled negative with one command. Done when `ruleprobe explain` prints every hit of a report run
over transcripts, redacted and writing nothing, and `ruleprobe label` writes a negative that
`ruleprobe corpus` then scores. This is field validity over corpus validity (maintainer decision 6).

## Scope and requirement coverage

- In: `ruleprobe explain` (FR-25: an explain path per hit, redacted, writing nothing); `ruleprobe
  label` (FR-26: one command turns a false positive into a labelled negative in a user-named corpus,
  redacted); one `redact` function beside `SECRET_PATTERNS`; a minimal YAML emitter for the closed
  subset; a proposed field-precision spike.
- Out: fixes or prescriptions for a wrong hit, any model call, any write by `report`, widening the
  row to carry hit keys (AD-13), rebuilding a native transcript from one event.

## Children

1. RP-S017 (#51): `ruleprobe explain` prints the event behind every hit, redacted.
2. RP-S018 (#52): `ruleprobe label` turns a false positive into a labelled negative.
3. RP-SP002 (#53): field precision per shipped detector from hand-sampled hits (proposed,
   maintainer to confirm).

## Architecture slice

- AD-6: The labelled corpus is the validity contract, and the floor is 0.9 (label keys only from
  `hit_key` and `event_key`; the `.events.jsonl` session format).
- AD-8: The package envelope: no dependency, no network, no write, no model, deterministic (the label
  command is the only writer).
- AD-13: Explain, label and redaction.
- AD-7: The declarative format is a closed YAML subset with JSON as its equal (the emitter adds no
  syntax).
- Components: `ruleprobe/cli.py`, `ruleprobe/report.py`, `ruleprobe/validity.py`,
  `ruleprobe/declarative.py`, `ruleprobe/detectors/common.py`.

## Sequencing

- RP-S017 depends on Epic 1 stories 1.5 and 1.8. RP-S018 depends on RP-S017. RP-SP002 depends on
  3.5, RP-S017 and RP-S018, and is sequenced before 6.2.
- Nothing in this epic runs in parallel with its own children; it can run beside Epic 5.

## Exit criteria

1. `ruleprobe explain` prints session, turn, tool-use id, detector id and matched field for every hit,
   and a test proves a known secret shape never appears.
2. `ruleprobe label` writes one `.events.jsonl` and one `near` label; `ruleprobe corpus` counts it.
3. `report` still writes and sends nothing, and no report number changes under explain.
4. `ruleprobe corpus --floor 0.9` passes in CI.
5. RP-SP002 is run or dropped by the maintainer, with the decision recorded.
