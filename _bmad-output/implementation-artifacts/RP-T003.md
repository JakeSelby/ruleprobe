## Goal

Make "runtime-neutral" a measured claim: every detector that applies to the third runtime, catalog
entries included, is scored on labelled sessions from that runtime and meets the 0.9 floor in CI.
SM-6 targets exactly this, with near-misses as its counter to easy sessions.

## Acceptance criteria

1. **Given** the corpus, **when** listed, **then** it holds at least one labelled session from each
   runtime read.
2. **Given** each detector that applies to the third runtime, catalog entries included, **when** CI
   scores it on those sessions, **then** it is at or above 0.9.
3. **Given** the third runtime's sessions, **when** reviewed, **then** they carry near-misses as well
   as positives.

## Tasks

- [x] Author synthetic native-runtime sessions for the third runtime (AC: 1)
- [x] Label positives and near-misses per applicable detector in `labels.yaml` (AC: 2, 3)
- [x] Run `ruleprobe corpus --floor 0.9` and fix or report any detector under it (AC: 2)

### Completion notes

- Three hand-authored Gemini CLI sessions in the native JSONL shape, read through the real reader:
  `gemini-shell.jsonl` and `gemini-git.jsonl` under `sessions/gemini-posix/`, whose `.project_root`
  is the POSIX path `/workspace/example-repo`, so `run_shell_command` reads as `Bash`; and
  `gemini-windows.jsonl` under `sessions/gemini-windows/`, whose root is a drive letter, so the
  shell stays native. Each project directory holds `chats/`, as Gemini's layout does, because the
  reader finds the root only from there. The project, paths and credentials are fictional.
- Applicable on Gemini, each with at least five positives and five near-misses on the two POSIX
  sessions alone, `gemini-shell.jsonl` and `gemini-git.jsonl`, all at 1.00:
  `transcript-hygiene/whole-file-cat`, `transcript-hygiene/unfiltered-find`,
  `verification/no-verify`, `secrets/secret-in-write`, and the catalog's
  `testing/test-after-change`, `git-safety/force-push-default`, `package-manager/pip-install`,
  `commits/non-conventional-subject` and `secrets/secret-file-add`. The count includes neither
  the Windows session nor RP-S019's `gemini-writes.jsonl`. `tests/test_corpus_gemini.py` holds
  them to that.
- Not applicable on Gemini, by the reader's design (RP-S019): `cache-hygiene/compact`, because
  `$set.messages` is not told apart from truncation, masking and rollback, so no `compact` event is
  made; `cache-hygiene/model-switch`, because no Gemini event carries a model; and every `Bash`
  detector on a session whose root is not POSIX, where the shell keeps its native name. The Windows
  session labels those shell calls `near`, so a mapping that leaked would score a false positive.
  They guard the mapping, not a detector's matching, and are not counted toward the bar.
  `tests/test_corpus_gemini.py` asserts that no hit lands on a shell call there, and that compaction
  and model-switch give no hit on any Gemini session. `tu-x6`, the test run after `tu-x5`, is
  unlabelled, because `testing/test-after-change` keys its hit on the change.
- Labelling the catalog entries in the corpus moves their rows from `examples` to `corpus`, since a
  detector the corpus labels is scored by its labels alone. Every row is now corpus-scored; no
  existing session fired a catalog detector before the labels were added.
- **Turn rule (RP-S019 decision 3): held.** A turn starts at a `user` record that is not all
  `functionResponse` parts. Every tool call in these sessions is followed by the `user` record of
  `functionResponse` parts Gemini writes back; several records carry two to seven calls; turn 2 of
  both POSIX sessions ends on a tool result with no text, and the next prompt follows it at once.
  Every label key carries its turn, so a wrong rule points labels at no event and the corpus load
  fails. Checked by patching the reader in memory: counting a `functionResponse` record as a turn
  fails at `1:tu-w2` in RP-S019's `gemini-writes.jsonl`, and at `1:tu-a3` in `gemini-shell.jsonl`
  with that session taken out; folding a prompt after a tool result into the turn before fails at
  `3:tu-a9` in `gemini-shell.jsonl`. The rule held against the documented
  record shapes; no real Gemini CLI transcript was on the build machine, so it is not verified
  against one.
- The sessions were written by a scratch script that serialises hand-specified records; it is not
  committed. The README table is the output of `python3 -m ruleprobe corpus --no-config`, pasted.
- `pyproject.toml`'s package data globs `corpus/sessions/**/*.jsonl` and
  `corpus/sessions/**/.project_root`, so the wheel and sdist carry sessions at any depth, a
  subagent's under `chats/<parent>/` included; `tests/test_contract.py` globs them recursively, as
  setuptools does. A wheel built with `build` 1.6.1 and installed outside the checkout passes the
  corpus gate.

### Review round 1

- **Near-miss bar counted the Windows mapping guards:** added POSIX near-misses for
  `whole-file-cat`, `unfiltered-find`, `no-verify`, `pip-install`, `secret-file-add`,
  `force-push-default` and `secret-in-write`, plus three `secret-in-write` positives; the test
  counts the POSIX sessions only, and a separate test asserts the Windows shell stays silent.
- **`5:tu-a18` was no opportunity for `test-after-change`:** the near label is dropped; the five
  near-misses are all changes with no later test run.
- **Windows tool ids collided with `gemini-writes.jsonl`:** renamed `tu-x*`; the turn-rule note
  names each file its check ran on.
- **No direct check that compaction and model-switch stay silent:** added.
- **`_registry()` ignored the fold map:** it passes `registry.fold_map()`, as the CLI does.
- **`RULEPROBE_CORPUS` was popped and never restored:** patched with `mock.patch.dict` and
  restored by `addClassCleanup`.
- **`corpus_transcripts()` missed legacy `.json` sessions and linked directories:** it counts
  them, walking with `followlinks=True`.
- **"five prompts, five turns" comment:** now "one turn per prompt".
- **Package-data globs not recursive:** made recursive. `corpus/sessions/**/*.json` is left out:
  it matches no file today, and `tests/test_contract.py` refuses a pattern that matches none. A
  legacy session added later without it fails the wheel test's corpus load, which names the
  missing file.
- **README overclaimed the Windows session:** it now says the session checks that shell detectors
  stay silent and does not measure them on PowerShell.
- **Call count and frontmatter:** "two to five calls" is now seven; the frontmatter is left to
  the sync script.
