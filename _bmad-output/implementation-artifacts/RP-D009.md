# RP-D009 — decision(detectors): the catalog's first shapes and how many

## Context

FR-16 ships declarative detectors for common rule shapes, bound to a rule by what it says, so a
stranger's rules are measured without a detector written. The catalog's size is open as PRD §11 Q3:
how many shapes must it hold before SM-1 can pass. SM-1's target is four of five first-time testers
seeing at least one of their own rules measured within a minute; its counter is catalog precision, so
no entry ships without `examples:` or under the 0.9 floor (AD-6, NFR-6). AD-12 fixes the binding: one
anchored pattern per entry, exact-one match. AD-7 limits entries to the closed matcher vocabulary.

The question: which named shapes ship in 0.2.0, with which detector kind, and how many.

## Options

1. **A small set.** For: each entry can carry `examples:` that clear the floor, and fewer patterns
   means fewer rules that match more than one entry and stay unmeasured. Against: SM-1 may fail if a
   tester's file states none of the shapes.
2. **A wide set.** For: more files bind at least one rule. Against: SM-1's counter warns that loose
   binding "lifts the measured share on rules nobody would recognise"; more patterns raise overlap,
   and each entry adds corpus work.

## Decision

Decided 2026-09-23 by the maintainer: the catalog is a small set of six to eight shapes, each with
`examples:` that clear the 0.9 floor. Binding stays exact-one match (AD-12). Each entry can carry
examples that clear the floor, and fewer patterns mean fewer rules that match more than one entry.

The starting list, with each detector kind:

1. Run the tests before finishing: `order` or `absent`.
2. Never skip pre-commit hooks with `--no-verify`: event matcher on `git`.
3. Never force-push the default branch: event matcher on `git`.
4. Use the named package manager, not another: event matcher on `command`.
5. Do not read a whole file into context: event matcher on `command`, as the shipped
   `whole-file-cat`.
6. Conventional Commit subjects: event matcher on the `git` commit message
   `[ASSUMPTION: subject parsing fits a matcher]`.
7. Never commit a secret-shaped file: event matcher on the `git add` path.

## Consequences

- RP-S016 is quicker to land at the floor; each listed shape ships only with `examples:` that clear
  it.
- SM-1 carries more risk: a tester whose file states none of the shapes sees no catalog match.
- The shipped ids join the list AD-9 versions; RP-SP001's timing is unaffected.
