## Reproduction

From #87, at `0d8bc4b`, with Claude Code transcripts under `~/.claude/projects/`:

- A project directory that was copied or renamed, or a worktree with a project folder of its own,
  leaves one session in several files: `<folder>/<session id>.jsonl` under two or three project
  folders, and the same for each subagent's `<session>/subagents/agent-<id>.jsonl`.
- `iter_sessions` yields one session per file, so each copy's hits count again, and every copy
  enters a share's denominator. One detector's 12 reported hits were 6 distinct ones.
- On one developer's machine, re-measured at `b73baca` by key only, nothing copied: 5,630 files
  read as 5,524 sessions, of which 2,267 addresses appeared more than once, 2,307 sessions too
  many. By shape: 80 parent sessions as identical copies and 10 differing, and 2,104 subagent
  sessions as identical copies and 77 differing; every copy had its original's file name, in
  another project folder.

## Root cause

`iter_sessions` in `ruleprobe/readers/__init__.py` reads each path `_paths` returns and yields
whatever `read` gives, and FR-1 promised exactly that: one session per transcript file. Nothing
compares sessions across files. `session_address` already treats `<runtime>:<session id>` as
unique, and `label` has to refuse an address that names two sessions, so the rest of the package
assumed an id is one session while the readers did not deliver it.

## Acceptance criteria

1. **Given** two identical transcripts of one session in two project folders, **when**
   `iter_sessions` reads them, **then** it yields one session, from the first in path order, and
   its hits are counted once.
2. **Given** two differing files carrying one session id, **when** they are read, **then** the one
   with more events is the session; on equal event counts, the first in path order.
3. **Given** a parent transcript and its subagent's own transcript, **when** they are read,
   **then** they stay two sessions, `<id>` and `<id>/<agent id>`; a subagent file copied into two
   folders is one subagent session.
4. **Given** copies set aside, **when** `errors` is passed, **then** each is recorded with `error`
   `COPY` and `kept` naming the file read; **and** the CLI's read note counts them in a clause of
   their own, apart from `produced no session`, naming each with its folder.
5. **Given** a copy with no event, or one older than `since`, **when** the group is read, **then**
   it is noted `no session in it` or dropped silently, as alone, and is never the one kept.
6. **Given** the same files, **when** the directory walk lists them in another order, **then**
   `iter_sessions` yields the same sessions in the same order with the same notes, each session
   where its group's first file falls in path order.
7. **Given** Codex rollouts carrying one session id, **when** they are read, **then** the same
   rule applies, keyed by the rollout's own `session_meta` id.
8. **Given** a labelled corpus whose files share a session id, **when** it loads, **then** every
   file is its own session, and two files of one name in different folders are still refused.
9. **Given** the shipped corpus, **when** `ruleprobe corpus --no-config --floor 0.9` runs, **then**
   it scores 1.00, as before.

## Design

Each reader gains `session_key(path)`, the id `read(path)` gives, computed by the same function
`read` uses: `_identity` and `_key` in the Claude Code reader, `_items` and `_key` in the Codex
reader. `iter_sessions` groups the paths by `(reader, key)` in a first pass, then reads each group
in order of its first path, keeps the session with the most events (the first on a tie), and
yields it. The rest are recorded in `errors` as `COPY`.

Design decisions:

1. **Pre-scan, not buffering.** A pre-scan of each file's key, then a read of each group, keeps
   `iter_sessions` streaming: two sessions are held at most. Buffering every session by id until
   the last file is read would hold the whole history at once, which `explain` is written to
   avoid. The cost, on the machine above (5,630 files): the key pass took 5.8 s, and a full
   `iter_sessions` 33.8 s against 26.3 s before, peak traced memory 524 MB against 503 MB. A
   parent file's key is decided by its opening lines; a subagent's own file must be read to the
   end, since its last line could still rule it out, and those are most of the files.
2. **One key function.** `session_key` and `read` share `_identity` (the first `sessionId`, and
   the agent id when every `user` and `assistant` line is one agent's sidechain) and `_key`
   (`<parent>/<agent>`, else the id, else the file stem). `_identity` stops once both are decided,
   so it serves a lazy line iterator and a list alike. A re-derived key would drift and merge a
   subagent into its parent.
3. **Most events, then path order.** A copy made mid-session is a prefix of the original, so the
   longer file is the fuller one. Path order is the tie-break because it is the order the walk is
   sorted into; nothing on disk, like a modification time, enters the choice (NFR-3).
4. **Candidates are files that would be sessions alone.** `since` and the no-event rule apply to
   each file first, so an old copy cannot hide a newer one, and an empty copy keeps its `no
   session in it` note: `COPY` means a session was read from another file, not a failure.
5. **Yielded where the group first appears.** The session comes out at its group's first path, so
   the order is a function of the sorted paths alone.
6. **Still once, if a file changes between the passes.** `iter_sessions` also remembers each
   `(runtime, id)` it yielded, so a file whose id changed after the key pass is set aside rather
   than yielded twice.
7. **Codex too.** A rollout's id is its own `session_meta`'s, so a copied rollout is the same
   session; the rule holds and is applied.
8. **The corpus reads per file.** A label names its session by file name, and a near-miss is often
   a copied positive, edited, so `load_corpus` reads through `iter_file_sessions`, the same reader
   path without grouping. Not added to the README's API list.
9. **The note names copies apart.** `_read_errors_line` prints `N transcript(s) produced no
   session: ...` for failures and `M transcript(s) set aside as copies of a session read from
   another file: <folder>/<file> (kept <folder>/<file>)` for copies; a copy and the file kept
   usually share a name, so each carries its folder.

Rejected: buffering by id (memory, above); a cheaper key read from the file name, which a
subagent file's content and a stem-only file do not follow; choosing by modification time, which
is not deterministic across machines; merging the events of differing copies, which would invent
a session neither file holds.

The fix must not change: how a single file reads, the order of sessions with no copies, the
`no session in it` notes, the `since` rule, and the corpus scores.
