## Context

FR-17 prints `promote?` above `promote_share` (default 0.30), and leaves its wording open (PRD Q11). The README says the marker means "either the rule is worth stating more loudly or the rule is wrong", which sits beside "ruleprobe prescribes nothing". Maintainer decision 1 puts prescriptions out of scope: ruleprobe is a measurement engine, not a doctor. The 0.2 break is the one place to change report wording.

## Options

1. **Keep `promote?`.** For: no change for existing readers or scripts that match the string. Against: it advises, which contradicts maintainer decision 1.
2. **Reword to a neutral marker, such as "frequent", with no advice.** For: keeps the threshold signal and makes the report descriptive. Against: a visible wording change in the break; `promote_share` and `--promote-share` names may then read oddly.
3. **Drop the marker.** For: the share column already carries the number. Against: loses a signal readers use to scan a long table.

## Decision

Open: the maintainer's answer to PRD Q11. The PRD recommends option 2: keep the threshold marker and give it neutral wording ("frequent") with no advice attached. [ASSUMPTION: reword to a neutral marker such as "frequent" with no advice, per the PRD's recommendation]

## Consequences

- Option 1: nothing changes in code; the README's advice line should still be reworded or it contradicts decision 1.
- Option 2: RP-S013 changes the note in `report_data` and `report`, the README report section, and the tests that assert the string; whether the parameter and flag are renamed is a contract question under AD-9.
- Option 3: RP-S013 removes the note and its README text; `promote_share` becomes unused and its removal is a contract change under AD-9.
