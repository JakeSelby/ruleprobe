# RP-D010 — decision(release): the success targets and window for 0.2.0

## Context

PRD §9 sets eight success metrics, SM-1 to SM-8, and a window running from the 0.2.0 release to
2027-03-23. The baseline on 2026-09-23 is 0 GitHub stars and 0 known outside users. The PRD tags
every target and the window as carried from the brief, not set by the maintainer, and PRD Q6 asks
whether they are right. Q6 is needed before the v0.2.0 release, because the release is judged against
these numbers.

The question: keep each SM target and the 2027-03-23 window, or change them.

## Options

1. **Keep every target and the window as written.** For: they are already testable, each has a
   cohort, a target and a counter-metric, and SM-1 mirrors the harness's own SM-1. Against: they were
   not set by the maintainer, so a miss may reflect an arbitrary number rather than the product.
2. **Change some targets or the window.** For: the maintainer owns the numbers the release is judged
   by. Against: it costs a PRD amendment through `bmad-prd` update intent, and changed targets must
   keep their counter-metrics so they are not tuned to pass.

## Decision

Open: the maintainer's answer to PRD Q6, target by target and for the window. The corpus records no
recommendation.

## Consequences

- **Keep:** no PRD change; the release is judged against PRD §9 as written, and the
  `[ASSUMPTION]` tag in PRD §9 is resolved by this record.
- **Change:** the PRD is amended through `bmad-prd` update intent in the same change, and every
  artifact that cites a changed SM (for example SM-4 in the contract work) is checked against the
  new number.
