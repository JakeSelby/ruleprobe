## Goal

Give ruleprobe the open-source delivery system it needs to ship on its own. The package shipped
0.1.0 with a licence, a README and one CI workflow, and nothing else of a delivery system. This
chore stands one up as ruleprobe's own, so the package can be planned, reviewed, released and
contributed to independently:

- BMad planning with `RP-` IDs;
- one delivery issue per pull request, enforced in CI;
- a tag-driven release that publishes to PyPI through trusted publishing;
- rulesets on `main`, `stable` and tags;
- the contributor surface a stranger reads before opening an issue.

## Acceptance criteria

1. **Given** a clean reinstall of BMad Method 6.12.0 with `project_name = "ruleprobe"`, **when** it
   completes, **then** only `_bmad/custom/` and `_bmad-output/` are tracked and tracked files are
   unchanged.
2. **Given** `scripts/bmad_issue_sync.py`, **when** a maintainer files or reserves work, **then** it
   allocates `RP-*` IDs; `audit` runs in CI, and a daily live-audit workflow exists.
3. **Given** any pull request, **when** CI runs, **then** the `issue-ownership` check runs, and the
   `main` ruleset requires it alongside `test`, `floor`, `corpus` and `package`.
4. **Given** a pushed `v*` tag, **when** the release workflow runs, **then** it re-runs the gates,
   builds once, publishes to PyPI with no stored token, creates the GitHub release from the
   changelog section, and advances `stable`.
5. **Given** a tag, `__version__` and changelog that disagree, **when**
   `scripts/release_preflight.py` runs, **then** it refuses; `scripts/release_notes.py` prints the
   version's section; both are tested.
6. **Given** a new contributor, **when** they open the repository, **then** CONTRIBUTING, SECURITY,
   SUPPORT, a code of conduct, CODEOWNERS, Dependabot, a PR template and three issue forms exist, and
   `AGENTS.md` carries the package contract with `CLAUDE.md` as its symlink.
7. **Given** the built sdist, **when** it is inspected, **then** it ships no test that imports
   `scripts/`.
