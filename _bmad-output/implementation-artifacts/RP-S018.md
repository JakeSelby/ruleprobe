## Story

As a developer who found a wrong hit,
I want one command to record it as a labelled negative,
so that the detector's score reflects the field, not only the corpus.

## Context and value

The shipped corpus is synthetic (AD-6), so a detector's score says how it does on hand-written
sessions, not on real ones. FR-26 asks for one command that turns a false positive into a labelled
negative in a user-named corpus, redacted. SM-8 targets at least ten corpus negatives from real false
positives. Today `ruleprobe/declarative.py` reads the YAML subset (`parse`, `load`) and has no writer,
and `ruleprobe/validity.py` loads native transcripts through readers only.

## Acceptance criteria

1. **Given** a hit key from explain and a corpus directory the user names, **when** `ruleprobe label`
   runs, **then** it writes one `<name>.events.jsonl` holding only that event and one `near` label for
   the detector's key, and nothing else anywhere.
2. **Given** that directory, **when** `ruleprobe corpus` reruns over it, **then** the new negative
   counts in that detector's score; the loader takes `turn` and `final` as written.
3. **Given** a session hit (`"<turn>:-"`), **when** label runs, **then** it refuses and says why.
4. **Given** an event holding a known secret shape, **when** labelled, **then** the shape appears in
   no written file.
5. **Given** redaction changes the field the detector matched, **when** label runs, **then** it
   refuses and says why.
6. **Given** `report`, **when** run after this lands, **then** story 1.10's no-write test still passes.
7. **Given** the CLI form `ruleprobe label --session <runtime>:<ID> --detector ID --key KEY --corpus
   DIR --name NAME`, with `report`'s source options and the shared detector options (narrowed: see Design
   decisions 16 and 22), **when** it runs,
   **then** it re-reads the transcripts, selects the one session with that runtime and id (narrowed: see Design decision 23), reruns the
   detector over it, and takes the event whose `event_key` equals KEY. It refuses, and says why, when
   no session or more than one matches, when the detector has no hit at KEY, or when
   `DIR/sessions/NAME.events.jsonl` already exists. [ASSUMPTION: this CLI form; AD-13 fixes only the
   subcommand name]
8. **Given** `DIR/labels.yaml` does not exist, **when** label runs, **then** it creates it with
   `version: 1` and a `sessions` list holding the one new entry (`session: NAME.events.jsonl`,
   `labels: [{at: KEY, near: [DETECTOR]}]`). **Given** it exists, **when** label runs, **then** it
   parses it with `declarative.load`, refuses if `NAME.events.jsonl` is already named or `sessions` is
   not the last top-level key, appends the new entry's text at the end, re-parses the whole file, and
   refuses and restores the original if the result is not the old document plus that one entry.
   [ASSUMPTION: append rather than rewrite, to keep a hand-written file's comments]
9. **Given** the package has a YAML reader and no writer, **when** label writes YAML, **then** it uses
   a minimal emitter in `ruleprobe/declarative.py` for the same closed subset the reader accepts, and
   a round-trip test asserts `parse(emit(value)) == value` for every value shape the label entry uses,
   including keys that need quoting such as `"1:tu-c1"`. [ASSUMPTION: a minimal emitter for the closed
   subset is the default]

## Design

### Approach

Label reuses explain's session selection and `redact` (RP-S017). It writes one event-schema session,
`<name>.events.jsonl`, which `validity` loads without a runtime reader, taking `turn` and `final` as
written (AD-6). Keys come only from `event_key` and `hit_key`. It is the only writer in the package,
and writes only under the directory the user names (AD-8, AD-13).

### Decisions and alternatives

1. A session hit is refused rather than writing the whole turn window, because one event cannot
   reproduce an `absent` or `order` hit (AD-13, recorded as an assumption there).
2. Refuse when redaction changes the matched field, because the written negative would pass trivially.
3. Append to an existing `labels.yaml` rather than rewrite it, to keep comments (assumption above).
4. The emitter adds no syntax the reader lacks, since AD-7 keeps the subset closed.
5. 2026-09-23: AC 5 is tested on the written bytes, since a `Hit` records no matched field. The
   event is serialized as it will be written, read back through `validity.read_events`, and the
   one detector is rerun over it with no stances, as the corpus runs. Label refuses unless it
   still hits at KEY. When the unredacted event alone hits and the written one does not, the
   message says redaction changed what the detector matched; when neither hits, it says the
   hit needs the events around it.
6. 2026-09-23: AC 4 is checked on the bytes, not the field values. After both texts are
   serialized, label refuses when `redact` would change either or any `SECRET_PATTERNS` shape
   matches in it. A JSON escape can complete a key name (`\u001c` then `lient_secret`), so an
   event that spells one only once escaped is refused rather than rewritten.
7. 2026-09-23: every string in the event is redacted, keys included. A mapping key that is
   secret-named, or would be redacted as `<key>: v`, is replaced by `[redacted]` with its whole
   value, because the value was redacted apart from the name that marked it.
8. 2026-09-23: `--name` is a plain file stem: not empty, no leading dot, no `..`, no path
   separator of either kind, no control character or line separator.
9. 2026-09-23: no partial state. Every refusal is decided before the first write. After
   writing, the corpus is read back with `load_corpus` and the one new session scored with
   `score_corpus`; unless the detector scores one negative and one false positive there, or on
   any error, the `.events.jsonl` is removed, a `sessions/` directory label made is removed, a
   `labels.yaml` it created is removed, and an appended one is rewritten from its original
   bytes.
10. 2026-09-23: `--corpus` must be an existing directory; label creates only `sessions/` inside
    it. `DIR/sessions` or `DIR/labels.yaml` being a link, or not a plain directory or file, is
    refused, so no write can land outside the directory. The session file is opened with
    `O_EXCL`.
11. 2026-09-23: `--session` takes only the `<runtime>:<id>` address, not the bare id `explain`
    also accepts, so "one session with that runtime and id" is exact.
12. 2026-09-23: a gated detector is refused: the corpus scores with no stances, so a negative
    for it would pass trivially. More than one event at KEY is refused as ambiguous. A retired
    detector id is labelled under its current id through the registry's fold map.
13. 2026-09-23: the appended entry uses the indentation of the first entry under `sessions:`, or
    two spaces. A `sessions` written in flow style (`sessions: []`) fails the read-back check and
    is refused. The emitter writes lists in block style, so a label reads `near:` then
    `- <id>` rather than the shipped corpus's `near: [<id>]`.
14. 2026-09-23: refusals go to stderr as `label: refused: <why>`, redacted, with exit code 2;
    success prints the two paths and the corpus command to stdout, redacted, with exit code 0.
15. 2026-09-23: the written event is one line of sorted-key, ASCII-only JSON.
16. 2026-09-23 (build review): `label` takes no `--stance`. AC 7 names "the shared detector
    options"; `--rules`, `--detectors`, `--no-config` and `--plugins` are kept, but a stance
    could never change the outcome, since every detector not enabled with no stances is
    refused. This replaces the earlier decision that took `--stance`.
17. 2026-09-23 (build review): a detector that raises, over the native session or over the
    lone written event, is refused with its error rather than read as no hit. The written
    event's hits for the detector must be exactly `[KEY]` before anything is written.
18. 2026-09-23 (build review): an existing corpus is read with `load_corpus` before the first
    write and refused if broken as it stands (an unlabelled session file, a stale label, bytes
    that are not UTF-8); a `sessions/` holding sessions with no `labels.yaml` is refused too.
19. 2026-09-23 (build review): after a failure every rollback step is attempted, and a failed
    one is named with what it left, exiting 2. Only an exception raised while scoring is
    reported as a detector raising; a `CorpusError` or `OSError` is a refusal; anything else is
    rolled back and re-raised with its traceback.
20. 2026-09-23 (build review): writes open with `O_NOFOLLOW` where the platform has it. Both
    paths are re-`lstat`ed just before each write, and `labels.yaml` is re-read and compared
    byte for byte before the append. Residual: a concurrent process that swaps the corpus
    directory itself, or `sessions/`, between the `lstat` and the `open` can still redirect a
    write; closing that needs `openat`-style directory descriptors, which label does not use.
21. 2026-09-23 (build review): `--name` also refuses Unicode format characters (Cf) and leading
    or trailing whitespace. `emit` refuses a value past `MAX_DEPTH` or holding itself with a
    `DeclarativeError`. `load_corpus` refuses two session files of one name in different
    subdirectories of `sessions/`; the shipped corpus has none.
22. 2026-09-23 (code review): `label` takes no `--plugins` either. `ruleprobe corpus` loads no
    plugin, so a negative labelled for a plugin detector could never be scored. With the
    `--stance` decision above, this narrows AC 7's "shared detector options" to `--rules`,
    `--detectors` and `--no-config`, and the printed `ruleprobe corpus` follow-up carries those
    three as label was given them, each part shell-quoted.
23. 2026-09-23 (code review): a Claude Code subagent's transcript carries its parent's session
    id, so an address can name several sessions. The detector is rerun over each, and the one
    with a hit at KEY is taken; none is "no hit at KEY", more than one is refused as ambiguous
    with "narrow --root or --since", since the address already fixes the runtime. When any
    transcript failed to read, the count is printed on stderr on success too.
24. 2026-09-23 (code review): a detector that raises while the written corpus is scored is
    named with its error, found by rerunning the session leniently; an exception from the
    analysis or the scoring code is reported as such. `emit` refusing the entry is a refusal
    when `labels.yaml` does not exist yet, as when it does.
25. 2026-09-23 (code review): rollback restores `labels.yaml` only while it holds the original
    bytes followed by some or all of the new entry, and then atomically, through a temporary
    file beside it and `os.replace`, so a failed restore leaves the file as it was. Anything
    else there is left and described. The read-back of `labels.yaml` guards its `fdopen` as the
    writes do.
26. 2026-09-23 (code review): `--name` also refuses `:`, a drive-relative path or an alternate
    data stream on Windows. The emptiness walk of `sessions/` follows links, as the readers do.
    The `.events.jsonl` suffix is reserved in `sessions/`, documented in the README and the
    `validity` docstring.

### Do not implement

- No rebuild of a native transcript from one event.
- No `fire` labels, no edits to the shipped corpus, no write by `report` or `explain`.
- No widening of the YAML subset.

### Completion notes

- `cli.cmd_label` implements AC 1, 3, 5 and 7 and the 2026-09-23 decisions under Design. It
  selects the session with `report.session_address`, reruns only the named detector, takes
  the event by `validity.event_key`, compares keys by `validity.hit_key`, and redacts with
  `detectors.common.redact`. Its stdout and stderr lines pass through `report._redact`.
- `validity.read_events` and `validity.load_events` read an event-schema session without a
  runtime reader and keep `turn` and `final` as written. `load_corpus` skips a
  `.events.jsonl` among the reader sessions and loads it through `load_events` instead.
- `declarative.emit(value, indent=0)` writes the closed subset in block style and raises
  `DeclarativeError` for anything that does not parse back to `value`.
- `report`, `explain` and the library paths are unchanged; `tests/test_envelope.py` still
  passes (AC 6). The new names are not added to the declared public API.
- The tests are in the new `tests/test_label.py` rather than in `tests/test_cli.py`,
  `tests/test_validity.py` and `tests/test_declarative.py`, to stay clear of parallel work in
  those shared files.

## Review findings

Build review, 2026-09-23 (blind, edge-case and verification-gap layers):

- A raising detector read as "no hit" in `_hit_keys`. Resolved: refused with its error, on
  the native session and on the written event; tested.
- A second hit on the written event was only caught by rollback after `fp == 2`. Resolved:
  the hits must be exactly `[KEY]` before writing; tested.
- A broken existing corpus was found only after writing. Resolved: `load_corpus` runs before
  the first write; an unlabelled file, a stale label and non-UTF-8 bytes are tested.
- The catch-all blamed a detector for every exception. Resolved: only a scoring exception is;
  `CorpusError` and `OSError` are refusals; anything else is re-raised after rollback. The
  test that mocked `KeyError` now asserts the re-raise.
- Rollback could stop at its first failed step, and a failed `fdopen` leaked its descriptor
  and left the events file unmarked. Resolved: every step is attempted and a failed one named;
  the mark is set before `fdopen`, which closes the descriptor on failure; tested.
- Races on the written paths. Resolved: `O_NOFOLLOW`, a re-`lstat` before each write, and a
  byte comparison of `labels.yaml` before the append; tested with an edit and a link swap.
  The directory-swap residual is recorded under Design.
- `--stance` could never change the outcome. Resolved: dropped from `label` and the README.
- `--name` accepted format characters and edge whitespace. Resolved and tested.
- `emit` could raise `RecursionError`. Resolved: `DeclarativeError` past `MAX_DEPTH` or on a
  self-reference; tested.
- Two session files of one basename silently replaced each other. Resolved: `CorpusError`;
  tested, with a check that the shipped corpus has no such pair.
- Missing tests: `labels.yaml` as a link (its target unchanged) and as a directory, more than
  one event at KEY, redaction changing the key, non-UTF-8 `labels.yaml`, and labelling twice
  into one corpus. Resolved: each added.
- The README said nothing is written to disk. Resolved: `report` and `explain` write
  nothing, and `label` writes only under the directory named.
- The long `__all__` line in `validity.py`. Resolved: wrapped.
- No `CHANGELOG.md` line. Resolved by the orchestrator at push.
