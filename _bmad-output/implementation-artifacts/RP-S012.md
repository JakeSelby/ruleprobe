## Story

As a downstream tool storing rows,
I want each row to carry opportunity counts beside hit counts,
so that compliance can be reported from stored rows without re-reading transcripts.

## Context and value

Rows are the stored unit: a downstream tool keeps `measure()` rows and reports from them later. Today `measure()` calls `run()` and writes `rules` (detector id to hit count) and, on a raise, `rules_errors`. Without a `compliance` map in the row, RP-S013 cannot show compliance from stored data. AD-11 fixes the map's shape and says `measure()`, not `run()`, calls each enabled detector's `opportunities` with `run()`'s isolation.

## Acceptance criteria

1. **Given** a session and a detector with `opportunities`, **when** `measure()` runs, **then** the row carries `compliance[detector_id] = {"opportunities": N, "followed": M, "undecided": U}`, where `N` excludes `U` (AD-11): an undecided opportunity is counted in `U` only.
2. **Given** a detector with no `opportunities`, **when** `measure()` runs, **then** it has no `compliance` entry.
3. **Given** a detector gated off by the run's stances, **when** `measure()` runs, **then** its `opportunities` is not called.
4. **Given** an `opportunities` callable that raises, **when** `measure()` runs, **then** the raise is recorded in `rules_errors` against that detector and every other figure stands.
5. **Given** `run()`, **when** called as in 0.1.0, **then** its arguments and return are unchanged.

## Design

### Approach

In `measure()`, after `run()`, iterate the registry's detectors in a sorted order (NFR-3), skip any whose `enabled(stances)` is false or whose `opportunities` is `None`, call `opportunities(events, ctx)` inside the same isolation `run()` uses, and fold the triples into `{"opportunities", "followed", "undecided"}`: `True` adds to both `opportunities` and `followed`, `False` to `opportunities`, `None` to `undecided` only. Write `compliance` only when at least one detector defines opportunities. [ASSUMPTION: a row with no opportunity-defining detector omits the `compliance` key rather than writing an empty map] The row's `schema_version` comes from story 1.5.

### Decisions and alternatives

- Calling `opportunities` from `run()` was rejected: AD-11 keeps `run()` and its return unchanged.
- The hook's form follows RP-D005.

### Do not implement

- No change to `report`, `report_data` or the CLI (RP-S013).
- No folding of `compliance` by renamed id here; the fold happens on read (RP-S013, AD-9).

### Completion notes

- `measure()` runs the detectors through `registry._run`, a private variant of `run()` that also returns the `Context` it built and the detectors it found enabled. Each enabled detector defining `opportunities` is then called, in id order, with that same `ctx` and `ctx.events`, so a compiled detector's one-entry memo hits and `followed` comes from the evaluation that gave the hit. The first version analysed the session a second time, which built a new event list, missed the memo and evaluated every compiled `order` and turn-scoped `absent` detector twice. The public `run()` and its return are unchanged.
- A raise, or a result that is not an iterable of `(turn, tool_use_id, followed)` triples with `followed` exactly `True`, `False` or `None` (the check deferred from story 2.4), is appended to `rules_errors` with `"hook": "opportunities"`, and that detector gets no `compliance` entry. A malformed result is named `MalformedOpportunities`, so it reads apart from a `TypeError` the callable raised. `None`, a string, a dict or a non-iterable result is malformed; an empty list is a zero tally.
- `errored_detectors` skips entries tagged `"hook": "opportunities"`, so an `opportunities` failure costs no hit figure and the report is unchanged. The tag is an additive field on a `rules_errors` entry.
- The `compliance` key is written when at least one *enabled* detector defines `opportunities`, so a row whose only such detectors are gated off omits it; a row where every one raised carries `{}`.
- A detector whose `fn` raised keeps its `compliance` entry.
- `compliance` is not added to the declared public API: `measure` and row keys are not declared in the README or `tests/test_contract.py`. The `run()` test compares the signature against the call shape the README declares.
- Tests: `ComplianceTests` in `tests/test_report.py`. Mutation checks, each a `sed` edit of `ruleprobe/report.py` followed by `python3 -m unittest discover -s tests -p test_report.py`, then the file restored:
  - `if followed is None:` made never true (undecided counted as not followed): `FAILED (failures=12)`.
  - The `followed is %r, not True, False or None` raise replaced by `pass` (non-bool `followed` accepted): `FAILED (errors=3)`.
  - `_compliance` handed a fresh `analyse(session.events)` instead of the run's `ctx`: `FAILED (failures=2)`.
  - The `"hook": "opportunities"` skip in `errored_detectors` disabled: `FAILED (failures=1)`.
  - Restored: `OK`.
