## Goal

This epic is proposed, and the maintainer may drop it (maintainer decision 2, 2026-09-23). If kept,
a user can run a separate, opt-in command outside the core install that drafts a declarative detector
from a rule's prose, for a person to review and commit. Done is observable: the command emits one
entry with `schema_version` and `examples:` that `compile_detector` accepts, and the core install
still has no dependency and makes no model call. No story here is in 0.2.0 unless RP-D011 says so.
Status: proposed.

## Scope and requirement coverage

In scope: FR-34 Opt-in drafting command, and the decision on where it lands (PRD Q4).

Out of scope, from FR-34's non-goals: binding rules at report time, scoring detectors, making a
drafted detector count before a person commits it, and shipping in the core install. A judge is
tracked under RP-E002, not here. Any model call in `ruleprobe report` stays out (maintainer
decision 2).

## Children

In delivery order:

1. RP-D011 (#59): decision(draft): whether the drafting command belongs in 0.2.0, a later minor or
   nowhere.
2. RP-S020 (#60): feat(draft): an opt-in command that drafts a detector from a rule's text.

## Architecture slice

- AD-8 The package envelope: FR-34, if built, ships outside the core install and the core never

- The spine's Deferred list fixes only this boundary; the rest of the design waits on PRD Q4.

## Sequencing

RP-D011 comes first and may close the epic. RP-S020 starts only if RP-D011 keeps it, and then also
depends on story 1.4 (`schema_version` on detector entries) and story 1.10 (the envelope tests).

## Exit criteria

- If dropped: the epic closes with RP-S020 closed unbuilt.
- If built: RP-S020's acceptance criteria pass, and story 1.10's envelope tests still pass with the
  command installed.
