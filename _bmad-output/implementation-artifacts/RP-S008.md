## Story

As a downstream tool storing rows,
I want each row and each `report_data` result to say which schema wrote it,
so that a later reader never counts a row under the wrong schema.

## Context and value

FR-28 puts a schema version on every row and every `report_data` result. In 0.1.0 `measure()` in
`ruleprobe/report.py` writes a row with a `rules` map and no version, and `report_data` excludes a row
only when it has no `rules` map (FR-20). The 0.2 break changes counts (#19), so a stored 0.1 row and
a 0.2 row are different measurements. Rows are what downstream ledgers keep, so this is the part of
the contract most likely to outlive a release. Depends on the value RP-D001 (#29) fixes.

## Acceptance criteria

1. **Given** a session, **when** `measure()` runs, **then** the row carries `schema_version` with the
   RP-D001 value.
2. **Given** a row with no `schema_version`, **when** it is reported, **then** it is read as schema 1
   and counted as today.
3. **Given** a row above the highest known version, **when** it is reported, **then** it is excluded
   from every count and denominator and reported as excluded, as FR-20 excludes a row with no `rules`
   map.
4. **Given** any rows, **when** `report_data` returns, **then** the result carries `schema_version`,
   and `--json` output is byte-identical across two runs.

## Design

### Approach

Per AD-9: `schema_version` on each row and each `report_data` result, absent meaning 1. `measure()`
writes the current value. `report_data` checks each row's version beside the existing `rules` map
check and counts a row above the highest known version in its own excluded tally, which `report`
prints next to the existing unmeasured count. The result dict gains a top-level `schema_version`. The
CLI's `--json` path emits it unchanged, under the explicit sorts AD-8 requires.

### Decisions and alternatives

- Type and value: fixed by RP-D001 (#29).
- A newer row is excluded and reported, not read best-effort: AD-9 states it, matching FR-20's
  treatment of a row with no `rules` map and NFR-4's under-count rule.
- [ASSUMPTION: a row whose `schema_version` is malformed (not an integer) is treated like a row above
  the highest known version; the corpus states only the "above" case]

### Do not implement

- No fold map changes (RP-S009) and no `compliance` field (Epic 2).
- No rewrite of stored rows; reading stays fold-on-read.

### Completion notes

- `SCHEMA_VERSION = 2` and `KNOWN_SCHEMA_VERSIONS = (1, 2)` live in `ruleprobe/registry.py`, and
  `report.py` imports them; `measure()` writes the first, and `report_data` counts a row only when its
  version (absent read as 1) is in the second. They sit in `registry` because story 1.4 (#32) needs the
  same set for detector entries, and under AD-1 both `matchers` and `report` import `registry` while
  `matchers` may not import `report`: one constant, so the two cannot drift at the next bump. A test
  pins `SCHEMA_VERSION == max(KNOWN_SCHEMA_VERSIONS)`.
- A row with any other value, above 2 or malformed (a string, a float, a boolean, `0`, a
  negative), is counted in `unknown_schema`, out of every count and denominator, and `report` prints a
  note beside the unmeasured one. The version check runs before the `rules` map check, since a newer
  schema may shape `rules` differently. [ASSUMPTION: `0` and negatives are excluded with the malformed
  case, matching story 1.4's treatment of an unknown entry version]
- The result gains top-level `schema_version` and `unknown_schema` keys. [ASSUMPTION: the key name
  `unknown_schema`; the story names the tally, not the key]
- `ruleprobe/cli.py` needed no change: `--json` already dumps `report_data` with `sort_keys=True` over
  rows in sorted path order. A test runs `report --json --validity` in two processes under different
  `PYTHONHASHSEED` values and pins the output byte-identical; it guards hash-order drift, while the
  sorted walk is what fixes row order.
- An explicit `schema_version: null` reads as absent, schema 1: a store with a nullable column writes
  null for every 0.1 row, and excluding them would drop them all. [DEFAULT, for the maintainer to
  confirm or override: AD-9 says only "absent means 1"]
