## Goal

Link the reference site, https://ruleprobe.jakeselby.com, from the package metadata, so the PyPI
page and installed metadata point readers at it. The site went live on 2026-09-24 serving v0.1.0.
It is built in a separate repository, JakeSelby/ruleprobe-site, from the README, the changelog and
the planning corpus at each release tag. Issue #67 closes with the PR that adds this link. Nothing
in the package changes. The README stays as it is, because the site maps its sections from the
README's H2 headings.

## Design

- **Decision:** the site goes in as `Documentation`, and `Homepage` stays the GitHub repository.
  PEP 753 treats `documentation` and `homepage` as well-known labels, so PyPI shows each under its
  own name.
- **Alternative rejected:** pointing `Homepage` at the site. Issues, releases and the source live
  in the repository, and the site is a reference built from it, so `Homepage` stays the repository.
- **No unit test:** no code, script or workflow reads `[project.urls]`, and a test that restates a
  URL proves nothing. The evidence is the built metadata (AC 1). CI's `package` check builds the
  same artifacts on every pull request, which proves the table parses, but it does not look for the
  URL.

## Dev notes

- Before this change, `[project.urls]` in `pyproject.toml` held `Homepage` and `Issues`. Nothing
  under `ruleprobe/`, `tests/`, `scripts/` or `.github/` reads the table.
- The package contract holds: no dependency is added and nothing under `ruleprobe/` changes.
- The URL reaches PyPI with the next release. The site pins a release tag and moves to each new
  release through its own repin workflow.
