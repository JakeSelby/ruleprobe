## Story

As a maintainer or agent delivering ruleprobe work, I want each issue's story file to be the design
record and every SDLC step routed through its BMad skill, so that the design of a change lives in
the repository beside the code rather than in issue bodies and uncommitted plans.

## Context and value

Story files here were 26-line stubs that said the issue owned the design, and `refresh` refused any
file that was not a byte-exact stub, so a story file could not hold design without breaking the
tool. The same shape was fixed in agent-harness: its story files became the design record
(JakeSelby/agent-harness#620, delivered by JakeSelby/agent-harness#629), and a repository rule
routes every operation through BMad and keeps the corpus current (JakeSelby/agent-harness#621,
delivered by JakeSelby/agent-harness#631). This story ports both, so ruleprobe follows the same
open-source SDLC while standing alone.

## Acceptance criteria

1. **Given** a typed story file with an enriched body, **when** `refresh` applies a new title or
   state, **then** only the frontmatter, the H1 and the managed block change, and the body is
   preserved byte for byte, including a byte-order mark and CRLF line endings.
2. **Given** the existing legacy stubs, **when** `upgrade` runs, **then** each converts to its
   kind's typed skeleton without losing content, all or none, and afterwards `upgrade --check`
   reports no stub left.
3. **Given** a pull request whose typed delivery story still holds placeholders in a required
   section, **when** `issue-ownership` runs, **then** it fails; a filled story passes, and a legacy
   stub passes with a notice.
4. **Given** a story file whose managed block is missing, duplicated or preceded by stray prose,
   **when** `audit`, `refresh` or `audit --delivery` reads it, **then** it is reported as malformed
   rather than silently skipped.
5. **Given** `docs/bmad-governance.md`, `AGENTS.md` and the `bmad-build` customization, **when** an
   agent starts a BMad workflow, **then** it loads the authority split, the routing map and the
   currency rule, and `bmad-build` reads the delivery story as its spec.
6. **Given** RP-C001, RP-C002, RP-C003 and this story, **when** `audit --delivery` runs on each,
   **then** it reports 0 findings.

## Design

### Approach

Port the deltas of agent-harness#629 and #631 onto ruleprobe's own copies instead of replacing the
files. The sync tool here is an older fork of the same file, so the #629 patch applied hunk for hunk
at an offset, except the new constants, whose context line (`GIT_TIMEOUT_SECONDS`) does not exist
here. That hunk, and the two hunks in `check_issue_ownership.py`, whose context (the origin's
`pull_number` import) does not exist here, were placed by hand. The ported tool gains:

- typed rendering from `scripts/bmad_story_templates/*.md`, one per kind, with chore sharing task's;
- the managed block after the H1, located by a fence-aware head parser (`parse_layout`,
  `artifact_layout`) that keeps a BOM, CRLF endings and whole-line comments above the H1
  (`is_whole_line_comment`);
- a positive legacy-stub test (`is_legacy_stub`) in place of "anything without markers";
- byte-preserving `refresh`, `upgrade [--id] [--check]` with rollback, and
  `audit --delivery N` with its section parser;
- `write_text_atomic` for every write, and a shape check in `load_manifest`.

The repository's constants stay: the `RP-` prefix, `JakeSelby/ruleprobe`, and the empty `EPICS`,
`DECISIONS`, `SPIKES`, `BUGS`, `AUTHORED` and `PARENTS` sets. `check_issue_ownership.py` gains
`require_story_depth`, which runs the tool's `audit --delivery` for the pull request's issue.

### Decisions and alternatives

- **Port the deltas, not the file.** Replacing the tool with the origin's copy would have dragged
  in unrelated origin-only behaviour and constants.
- **Standalone governance text.** Where #631 says the origin's plan-approval artifact is distilled
  into the story at build, the text here says that an approved plan's detail is written into the
  story file at build, whatever produced the plan. No origin tooling is named.
- **No PRD, spine or UX yet.** The currency rule's amendment clause applies once such a document
  exists. [ASSUMPTION: the clause is kept conditional rather than dropped, so it binds the first
  PRD without another rule change.]
- **Sprint status wording.** The origin says the sync tool generates sprint status; this tool does
  not, so the rule here says sprint status is derived from `issue-map.json` and the GitHub record
  and never hand-edited.
- **No changelog line.** `AGENTS.md` asks for one only for a user-visible change, and
  `scripts/release_preflight.py` refuses a tree with Unreleased entries between releases. This is
  repository tooling; the package's behaviour does not change.
  The origin's changelog fragments, `changelog.d/620.added.md` and `changelog.d/621.changed.md`,
  were not ported: ruleprobe has no `changelog.d`, and adds `CHANGELOG.md` entries only for
  user-visible changes.

### Do not implement

- The origin's sibling-worktree ID collision check (`--advance`, `survey_ids_elsewhere`); it is a
  separate change.
- A merge-queue path in `issue-ownership`; this repository's workflow runs on pull requests only.
- Any dependency on the origin project's tooling.

  because every real file here is already typed.
