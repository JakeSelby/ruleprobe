## Goal

Cut ruleprobe 0.2.0 with a contract that matches what agent-harness imports on the day it ships, so
the harness bumps its pin with no code change (agent-harness AD-13). It runs last in the release,
after every in-scope item in Epics 1 to 5, RP-D010, and story 4.3 if the maintainer confirms it.
Binds FR-30 Declared public API, FR-31 Versioning policy, and AD-9 The contract is versioned, once,
in 0.2.0.

## Acceptance criteria

1. **Given** agent-harness `main` on the release day, **when** its ruleprobe imports, call shapes and
   non-name dependencies are re-derived, **then** the contract test is updated in the same change and
   passes, and the harness commit read is recorded.
2. **Given** `CHANGELOG.md`, **when** the version section is cut, **then** it names the 0.2 break
   (story 1.9).
3. **Given** `scripts/release_preflight.py`, **when** run in a fresh clone, **then** it is clean, and
   the wheel is published by the release workflow.

**The derived surface.**

- Imports: root `Registry`, `analyse`, `counts`, `run`; `ruleprobe.detectors.common` (as a
  module: `DETECTORS`, `SECRET_PATTERNS`, `__file__`); `ruleprobe.events` `hit`, `input_of`,
  `text_of`; `ruleprobe.registry` `Detector`, `Registry`; `ruleprobe.shell` `MAX_COMMAND`,
  `MARKER_RE`, `SUB_PLACEHOLDER`, `git_calls`, `has_redirect`, `normalise`, `operands`,
  `pipelines`, `strip_heredocs`; `ruleprobe.declarative` `load`; `ruleprobe.validity` `Score`,
  `CorpusError`, `DEFAULT_FLOOR`, `below_floor`, `score_corpus`, `scores_as_dict`,
  `validity_table`; `ruleprobe.__file__`. The same set as FR-30.
- Call shapes: `fn(events, ctx)` returning `(turn, tool_use_id)` tuples; `ctx.bash`,
  `ctx.finals`; `Parsed.event`, `.command`, `.heredocs`, and in the harness tests `.skipped` and
  `.pipelines`; `analyse(events).bash`; `MARKER_RE.match(v).group(1)`; `hit(e)`,
  `hit(e, tool_use_id=False)`; `git_calls(parsed, ("commit",))` 3-tuples; `pipelines`,
  `operands`, `strip_heredocs`, `normalise` with their exact nested shapes; `Detector` built with
  four or five positional arguments, subclassed with `__slots__ = ()` and `kind`/`stance`
  properties, `.id .rule .event .fn .gate` read on `common.DETECTORS`; `Registry(list)`;
  `run(events, stances, registry=, strict=, errors=)` returning `{id: [hit]}` with empty
  detectors omitted, each hit a 3-sequence `(id, turn, tool_use_id)`, and `errors` entries stored
  in ledger rows; `counts(events)` with keys `web_search`, `agent`, `ask_user`;
  `score_corpus(registry=, directory=)`; `Score(id).add`, `.scored`, `.precision`, `.recall`,
  `.detector`; the three floor helpers positional; `scores_as_dict` extended and dumped as JSON;
  `declarative.load(path)` returning `(document, lines)`.
- Non-name dependencies: `SECRET_PATTERNS` a plain `ast.Assign` of a literal list, read out of the
  wheel member `ruleprobe/detectors/common.py` and each pattern `re.compile`d; the wheel
  `ruleprobe-<version>-py3-none-any.whl` on `sys.path` as a zip; the corpus at
  `ruleprobe/corpus/`, found by walking up from `ruleprobe.__file__` to the zip and extracting;
  detector `event` values `bash`, `write`, `agent-brief`, `assistant-final`, `session`;
  `common.DETECTORS` exactly the six generic ids; the harness's own corpus in the scorer's layout
  with an extra top-level `known_below_floor`; the shipped `labels.yaml` read by pattern as
  `fire:`/`near:` flow lists, and its labelled ids asserted equal to the six generic ids.

**Differences from FR-30** (taken from `1307113`): no import name added or removed. FR-30 did not
list `Detector` with the gate omitted, the accepted `event` values, `run`'s return shape and hit
arity, `Parsed.skipped` and `Parsed.pipelines`, the exact shell-helper shapes, the six generic
ids, `counts` keys, the SECRET_PATTERNS zip-member read and compile, the consumer corpus layout,
or the shipped labels read by pattern. Each is now pinned in `tests/test_contract.py` and named in
the README, except the last clause below.

**Open, for the orchestrator:** the harness's
`test_the_docs_say_how_many_detectors_the_two_corpora_score` asserts the wheel's `labels.yaml`
labels exactly the six generic ids. The unreleased tree labels eleven (the catalog's five as
well), so that harness test fails on 0.2.0 with no harness change. Checked by running the
harness's ruleprobe-facing tests at `40cc0b7` against a wheel built from this tree: that is the
only new failure.
