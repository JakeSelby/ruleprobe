# RP-E005 — Epic 3: A stranger's own rules measured in a minute

## Goal

A developer with an unedited `CLAUDE.md` or `AGENTS.md` sees some of their own rules measured, with no
detector written and no model in the loop (maintainer decision 7), and sees the share of their rules
that is measured. The epic is complete when a named fixture rule file of several sections yields one
rule per section, its catalog-shaped sections report as measured and catalog-bound, the coverage block
prints the measured share, and one timing of `report --rules --since 30` on the reference volume is
recorded against NFR-9.

## Scope and requirement coverage

In scope (planned, v0.2.0):

- FR-14 Measured share: the coverage block prints measured, dark and unmeasured counts and the share
  (RP-S014). Status today: partial; 0.1.0 prints the three counts and no share.
- FR-15 Section-level binding: one rule file becomes many rules, one per split unit (RP-D008 fixes the
  unit, RP-S015 builds it). FR-13 Per-file binding is held unchanged for a file bound in front matter.
- FR-16 Catalog of common rule shapes: shipped declarative detectors bound by an exact-one anchored
  match (RP-D009 fixes the shapes, RP-S016 builds them), under FR-23 and FR-24's floor and examples.
- NFR-9 Time to first answer: one measured timing on a reference volume (RP-SP001).

Out of scope: any model call in binding or in `report` (NFR-7, maintainer decision 2); a drafting
command that writes detectors from prose (FR-34, PRD Q4); prescriptions or fixes for unmeasured rules.

## Children

In delivery order:

1. RP-D008 (#45): decision(rules): the section split unit.
2. RP-D009 (#46): decision(detectors): the catalog's first shapes and how many.
3. RP-S014 (#47): feat(rules): print the measured share in the coverage block.
4. RP-S015 (#48): feat(rules): split a rule file into one rule per section.
5. RP-S016 (#49): feat(detectors): a shipped catalog of common rule shapes, bound by exact-one match.
6. RP-SP001 (#50): spike(report): time the sixty-second path on a reference volume.

## Architecture slice

- AD-12 Rule binding and rule ids: `ruleprobe/rules.py` owns binding and the id; section ids are
  `<path>#<heading-slug>`; catalog entries carry one anchored pattern and bind on an exact-one match.
- AD-1 Dependency direction: `detectors.catalog` is placed in the graph, imported by `rules`, importing
  only `matchers`.
- AD-6 The labelled corpus is the validity contract: every catalog entry is scored and meets 0.9.
- AD-7 The declarative format: catalog detectors are declarative only.
- AD-9 The contract is versioned: catalog entries are Python literals in `ruleprobe/detectors/catalog.py`.
- AD-14 Shared registry state is never mutated after import: the catalog builds from `DEFAULT.copy()`.

## Sequencing

- RP-D008, RP-D009 and RP-S014 have no dependencies and can run in parallel.
- RP-S015 depends on RP-D008 and RP-S014.
- RP-S016 depends on RP-D009 and RP-S015, and on stories outside this epic: RP-S007 (schema_version on
  detector entries), RP-S009 (persisted fold map and shipped-id test) and RP-S011 (opportunities for
  order and absent detectors).
- RP-SP001 depends on RP-S016, so it times the path with the catalog in place.

## Exit criteria

- Every child is closed, each decision recorded with its chosen option.
- `ruleprobe corpus --floor 0.9` passes in CI with every catalog entry scored.
- The named catalog fixture test and the three-sections fixture test pass in `tests/test_rules.py`.
- RP-SP001's result is recorded with its command and machine class; a "not within 60 s" result has a
  filed follow-up.
- The README's "Sixty seconds on a rule of your own" section describes the catalog path.
