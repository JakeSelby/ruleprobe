## Story

As a developer on the third runtime,
I want `ruleprobe report` to read my sessions,
so that the same detectors measure my rules.

## Context and value

ruleprobe reads two runtimes today: `RUNTIMES` in `ruleprobe/readers/__init__.py` holds
`claude-code` and `codex`. Runtime-neutral is a claim until a third reader lands (maintainer decision
5). FR-4 already fixes how a runtime is added: one module with `ROOT`, `transcripts(root)`,
`read(path)` and one `RUNTIMES` entry. The runtime itself is chosen by RP-SP003.

## Acceptance criteria

1. **Given** `--runtime <name>`, **when** run, **then** that runtime's sessions are read, and `auto`
   includes them.
2. **Given** its shell tool, **when** read, **then** it reaches detectors as `Bash` with `command`;
   file tools map to the canonical names or stay native, never lossily.
3. **Given** a malformed line, an unreadable file and a missing `ROOT`, **when** read, **then** the
   line is skipped, the file lands in `errors`, and the missing root yields nothing and no error.
4. **Given** `turn` and `final`, **when** derived, **then** they follow AD-2 exactly as the other
   readers do.
5. **Given** the reader lands, **then** at least one labelled synthetic session from the runtime is in
   the corpus, and the README names the runtime and what its transcripts do not record.

## Design

### Approach

One new module in `ruleprobe/readers/` that imports `ruleprobe.events` only, with `ROOT`,
`transcripts(root)` returning sorted paths, and `read(path)` returning a `Session`, plus one
`RUNTIMES` entry (AD-10). It owns one module-level tool-name table, as `ruleprobe/readers/codex.py`
maps `exec_command` to `Bash`, and keeps the native key beside the canonical one (AD-3). `turn`
increments on every `user_prompt`; `final` is the last `assistant_text` before the next
`user_prompt` or the end (AD-2). The module takes its place in the dependency graph and the spine is
updated in the same change (AD-1).

### Decisions and alternatives

- The runtime is decided in RP-SP003, not here.
- A native tool with no exact canonical twin keeps its native name and under-counts, rather than a
  lossy mapping that gains a hit (AD-3, AD-4).
- 2026-09-24, maintainer: **no compaction event.** `$set.messages` cannot be told apart from
  truncation, tool-output masking and rollback, so the reader ignores it and emits no `compact`;
  `cache-hygiene/compact` never fires on Gemini, and the README note says so (AD-4, AD-10).
- 2026-09-24, maintainer: **Windows shell.** `run_shell_command` is `Bash` with `command` when the
  session's `.project_root` is a POSIX path; a root starting with a drive letter keeps the shell
  native, unmeasured by `Bash` detectors, and the README note says so.
- 2026-09-24, maintainer: **turns.** A turn starts at a `type: "user"` record that is not all
  `functionResponse` parts. Accepted as the rule; the labelled sessions of #56 (RP-T003) verify it.
- 2026-09-24, maintainer: **`invoke_agent` stays native** until its arguments are checked against
  `Agent`'s, so `Agent` detectors under-count on Gemini; the README note says so.
- From RP-SP003's Result: `write_file` is `Write` and `replace` is `Edit`, exactly, with their
  native keys (`instruction`, `allow_multiple`) kept; every other tool stays native. Messages are
  keyed by `id`, last line wins, first appearance fixes the order. `$rewindTo` is ignored, so rewound
  calls are kept. `info`, `error` and `warning` records are skipped. `final` is the last `gemini`
  record with non-empty, non-thought text before the next prompt. `model` is read from each
  `gemini` record [superseded by build-time decision 11, 2026-09-24]. A relative `file_path` resolves against `.project_root`. A subagent file under
  `chats/<parent>/` is read as its own session. The default root is `~/.gemini/tmp`.

### Build-time decisions

Each is a conservative default taken where the design was silent, headlined for confirm or override.

1. **An unknown project root keeps the shell native.** With no `.project_root` above the session the
   platform is not known, so `run_shell_command` is not mapped, the repo is empty, and a relative
   `file_path` is left as written. The shipped corpus session sits outside a project directory, so
   its shell call is labelled a near-miss for `whole-file-cat` rather than a hit. As built, the rule
   is POSIX roots only: a drive letter, a UNC path and a missing root all keep the shell native.
2. **A relative `file_path` resolves only against a POSIX root**; under a Windows root it is left as
   written.
3. **The legacy `.json` is read, and a `.jsonl` of the same name beside it wins.** `gemini.transcripts`
   lists both; with `--root`, `iter_sessions` walks `.jsonl` only, as it does for every runtime, so a
   legacy file is read from the default location and not from a named root (Still open)
   [superseded by decision 12, 2026-09-24].
4. **An `assistant_text` is emitted only for non-empty, non-thought text**, so `final` is the last
   such event, as AD-2 words it.
5. **A session file is one under a `chats` directory**, so other files under `~/.gemini/tmp` are
   never read as sessions. The `chats` directory must sit at or below the root being walked.
6. **`auto` decides a file as Gemini** when its first line carries a string `sessionId` and a string
   `projectHash`; no Claude Code line carries `projectHash` [widened by decision 13, 2026-09-24].
7. **A prompt's text is its `displayContent`** when the record has one, since `content` may carry
   expanded file contents, and otherwise its `content`.
8. **A tool result is read from `toolCalls[].result`**: its text parts and each `functionResponse`'s
   `output`, or its `error` when the call failed. A call with no result makes no `tool_result`.
9. **A `user` record with no parts is a prompt**; only a non-empty all-`functionResponse` record is
   skipped.
10. **Tests build their session trees in a temporary directory**, in the new
    `tests/test_reader_gemini.py`: a Gemini `.jsonl` under `tests/fixtures/` would change the
    mixed-root counts other suites pin, and `tests/test_readers.py` may be edited in parallel.
11. **2026-09-24, awaiting Jake's confirmation: no model on Gemini events.** Gemini's router and
    quota fallback change `model` without anyone choosing it, and the record does not say which, so
    counting changes would over-count (AD-4). Every Gemini `assistant_text` carries `model: ""`, the
    documented type with no value, and `cache-hygiene/model-switch` never fires on Gemini. The corpus
    session's two model changes are labelled near-misses; the README note states the gap.
12. **2026-09-24: `--root` reads Gemini's layout.** With `--runtime gemini`, `iter_sessions` lists
    through `gemini.transcripts(root)`, so only files below a `chats` directory at or under the root
    are read, legacy `session-*.json` included. With `auto`, every `.jsonl` is decided by its first
    line as before, and legacy `.json` files below `chats` are added.
13. **2026-09-24: `auto` also recognises a Gemini file opening on a message record**, a `$set` or a
    `$rewindTo` (`gemini.recognises`), none of which a Claude Code or Codex line matches.
14. **2026-09-24: a subagent session's id is `<parent session id>/<its own session id>`**, from the
    directories between `chats/` and the file, matching #86's Claude Code form and unique even when
    the file repeats its parent's id. `.project_root` is found by walking up to `chats/` at any depth.
15. **2026-09-24: shape guards.** Missing or non-object `args` read as `{}`; a non-list `messages` on
    the metadata line is ignored; an empty `displayContent` falls back to `content`; an empty result
    (`[]` or `{}`) makes no `tool_result`; a relative `file_path` whose `..` climbs out of the root is
    left as written.

### Do not implement

- No new event kind or field unless added to `events.py` first in this change (AD-2).
- No detector that branches on the runtime.
- Full near-miss coverage at the floor is RP-T003; this story lands one labelled session.

## Review findings

Code review, round 1 (2026-09-24), four layers: blind hunter, edge-case hunter, verification gap,
acceptance auditor. Every item was patched:

- **`--root` ignored decision 5 and the legacy format:** a named root now walks through
  `gemini.transcripts`, with `chats` counted only at or below the root, and `auto` adds legacy
  `.json` files (decision 12). Tested through `iter_sessions`.
- **`auto` missed a Gemini file opening on a message record:** `gemini.recognises` (decision 13).
- **`input` could be a non-dict:** missing or non-object `args` read as `{}`; a Gemini case joins
  `tests/test_contract.py`'s `EventTests`.
- **Subagent ids could collide with the parent's:** `<parent>/<own>` (decision 14).
- **Router and fallback model changes would over-count:** no model on Gemini events (decision 11,
  awaiting confirmation); the corpus labels and the README follow.
- **Shape crashes and gaps:** a non-list `messages`, a file name with no dot, an empty
  `displayContent`, an empty result, a session nested deeper under `chats/`, and a path climbing out
  of the root (decision 15), each tested.
- **Missing tests:** an empty-content `user` record is a prompt (decision 9); no result and text
  parts in a result (decision 8); a turn with no `assistant_text` has no `final` (AC 4).
- **README:** `.project_root` is in the project directory above `chats/`, and the shell rule is
  stated as POSIX roots only.
- **Story and spine:** `tests/fixtures/` dropped from Files to touch; the AD-1 and AD-3 amendments
  logged in the spine's memlog.
