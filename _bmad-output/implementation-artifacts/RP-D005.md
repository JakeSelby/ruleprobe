# RP-D005 — decision(registry): how a Python detector declares an opportunity

## Context

PRD Q10 asks how a Python detector declares an opportunity; it blocks FR-21 for Python detectors, the harness's own included. Downstream tools write detectors as `fn(events, ctx)` and construct `Detector` positionally, so any hook must leave both unchanged (FR-6, FR-30). AD-11 proposes a keyword-only `opportunities` attribute: a callable over `(events, ctx)` returning `(turn, tool_use_id, followed)` triples, `followed` being `True`, `False` or `None` for undecided. Today `Detector.__init__` takes `id, rule, event, fn, gate=None, examples=None` and declares `__slots__`, so a new attribute needs a slot.

## Options

1. **Confirm AD-11: keyword-only `opportunities` callable returning triples.** For: `fn` and its return shape do not move; matchers and Python detectors share one shape; a detector opts in without changing existing code. Against: a second callable per detector, which can disagree with `fn` unless the author derives both from one evaluation, as the compiler does.
2. **Widen `fn`'s return to carry opportunities.** For: one evaluation, no drift between hits and opportunities. Against: changes the return shape every downstream detector relies on, which AD-11 exists to prevent.
3. **A separate registry-level hook keyed by detector id.** For: `Detector` does not change. Against: a second place to look for a detector's behaviour, and it must follow renames through the fold map.

## Decision

Open: the maintainer's answer to PRD Q10. The corpus recommends option 1 as AD-11 writes it; the positional constructor and `fn` stay unchanged under every option.

## Consequences

- Option 1: RP-S011 adds a slot and a keyword-only parameter; the contract test (story 1.8) covers it; RP-S012 calls it behind the `enabled(stances)` gate with `run()`'s isolation.
- Option 2: a breaking change to every Python detector, including the harness's, outside the one 0.2 break AD-9 plans.
- Option 3: AD-11 and the spine change, and the fold function must resolve hook keys too.
