## Reproduction

From #86, at `46f3528`, on Claude Code versions that write each subagent to
`<session>/subagents/agent-<id>.jsonl`:

- Every line of that file carries `isSidechain: true`, an `agentId` naming the subagent, and the
  parent's `sessionId`. Its first message line is a `user` line whose content is the subagent's
  prompt, as a string.
- `claude_code.read(path)` over such a file returns a `Session` whose `id` is the parent's session
  id and whose `events` is empty.
- On one developer's machine, during the field-precision spike (#53), 5,002 of 5,510 sessions read
  were such empty files. Every tool call a subagent made went unmeasured, and every share's
  denominator counted the empty files, so shares read about thirteen times too low.

## Root cause

`read` in `ruleprobe/readers/claude_code.py` sets `sidechain` from each line's `isSidechain` and
skips every sidechain `user` and `assistant` line and every sidechain compaction line. That is right
for an older parent file, where sidechain lines are another agent's work, and the module docstring
already says the subagent's own file "is read as its own session". Nothing in `read` tells the two
files apart, so the subagent's own file loses every line. `read` then returns a session whenever a
`sessionId` was seen, events or none, so each such file became an empty session under the parent's
id and entered every denominator.

## Acceptance criteria

1. **Given** a transcript in which every `user` and `assistant` line is `isSidechain` and names the
   same non-empty `agentId`, **when** `claude_code.read` reads it, **then** it is a session whose
   `id` is `<parent sessionId>/<agentId>` and whose events are its lines, wherever the file sits and
   whatever `system`, `attachment` or `summary` lines it also holds.
2. **Given** that subagent file, **when** it is read, **then** its first `user` line is the
   `user_prompt` of turn 1, tool results start no turn, each later prompt starts the next turn, the
   last assistant text of each turn is `final`, models and compactions are read, and the detectors
   fire on its tool calls.
3. **Given** a parent file holding its own lines and sidechain lines, with or without an `agentId`
   on either, **when** it is read, **then** the sidechain lines make no event and its id is its
   `sessionId`, as before.
4. **Given** a file whose message lines name two agent ids, or whose sidechain lines name none,
   **when** it is read, **then** it is not treated as a subagent's own file.
5. **Given** a transcript of either runtime that yields no event, a Codex rollout with a session id
   included, **when** its reader reads it, **then** it returns None, and `iter_sessions` records it
   in `errors` as `no session in it`, in path order; **and** one whose last timestamp is older than
   `since` is dropped without a note, as before the fix.
6. **Given** the README's `ruleprobe label` section, **when** it describes sessions, **then** it
   says a subagent's own transcript is its own session keyed as `<parent session id>/<agent id>`,
   and a transcript with no event is no session.
7. **Given** a subagent session's address, `claude-code:<parent sessionId>/<agentId>`, **when** it is
   passed to `explain --session` and `label --session`, **then** each finds the session.
8. **Given** the shipped corpus, **when** `ruleprobe corpus --no-config --floor 0.9` runs, **then** it
   scores the same as before the fix.

## Design

The fix is in the two readers and `iter_sessions`. The Claude Code reader reads each file once into
a list of line objects. `_own_agent(entries)` returns the agent id when every `user` and `assistant`
line is `isSidechain` and all of them name one and the same non-empty `agentId`, else `""`. When it
returns an id, `read` treats sidechain lines as the file's own and keys the session
`<parent sessionId>/<agentId>`; otherwise sidechain lines stay skipped. Both readers return None for
a transcript that yields no event.

Design decisions:

1. **Content, not path.** The file is recognised by its lines, not by `subagents/agent-*.jsonl`: a
   path layout can move or be copied into a corpus, while the line shape is what makes the lines
   this file's work. A parent file always holds its own non-sidechain lines, so it can never pass.
   A file holding only one agent's sidechain lines reads as that agent's own, by design: nothing in
   it tells the two apart, and its lines are that agent's work either way.
2. **Only `user` and `assistant` lines decide.** They carry the work. A `system`, `attachment` or
   `summary` line written without the markers cannot turn a subagent's file back into an empty
   one. A `compact_boundary` inside a subagent's own file still emits a compaction, as in a parent.
3. **One agent id, strictly.** Sidechain lines without an `agentId`, or naming two ids, are read as
   a parent's. Treating them as a subagent's own would guess, and NFR-4 prefers the quieter report.
4. **The id is `<parent sessionId>/<agentId>`.** The parent's `sessionId` alone would give the
   parent and each of its subagents one address for `explain` and `label`; the agent id alone is
   short and not promised unique across sessions. Together they stay unique and name the parent.
   A file with no `sessionId` is keyed by the agent id alone. `session_address` joins runtime and
   id with `:` and `explain` and `label` compare the address as a string, so the slash needs no
   change there. No new `Session` field, since the public API is what the README lists.
5. **One read.** The file is read once, and ownership is decided on the lines the events are built
   from, so a live file appended between two passes cannot be judged on one set of lines and read
   on another.
6. **No event, no session, in the readers.** `read(path)` returns None, the same signal as a file
   with no session in it, and the note stays `no session in it`. `iter_sessions` calls
   `read(path, empty=True)`, which returns a session-bearing transcript with no events, so the
   `since` cut-off drops an old one silently, as before the fix, and only then is the rest noted.
   The Codex reader takes the same flag, since the decision is about what counts as a session, not
   one runtime. `measure` never sees a row with nothing measurable. The output stays deterministic:
   lines are read in order and the notes come in path order.

Rejected: reading the parent's file and its `subagents/` directory together as one session, which
would merge two agents' turn numbering and final messages; and dropping empty sessions only in
`iter_sessions`, which would hand them to a caller of `read`.

The fix must not change: how a parent file reads (turn numbering, `final` messages, compaction,
models, the de-duplication of a block written twice); how a Codex rollout with events reads; the
shipped corpus scores.
