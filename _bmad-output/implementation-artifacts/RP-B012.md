# RP-B012 — fix(readers): --runtime gemini and auto read the same Gemini files under a root

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

Over the shipped corpus, `iter_sessions(root="ruleprobe/corpus/sessions")` reads four Gemini
sessions and `iter_sessions(..., runtime="gemini")` reads three, both with empty `errors`:
`gemini-writes.jsonl` sits outside any `chats` directory, so only `auto` reads it (Epic 5's
retrospective, finding F5). A synthetic tree with one session under `proj/chats/` and a copy
outside `chats` gives the same split.

## Root cause

`readers._paths` took two rules under a named root. `--runtime gemini` listed through
`gemini.transcripts(base)`, which keeps only files below a `chats` directory at or under the root
(RP-S019 decisions 5 and 12). `auto` walks every `.jsonl` and decides each by its first line
through `_detect`, so a Gemini-shaped file anywhere is Gemini's. Neither path records what the
other reads and it skips. `_detect` also returns `None` for a file it cannot open, and `_paths`
dropped that file under `auto`, so an unreadable file vanished there too.

## Acceptance criteria

1. **Given** a named root holding a Gemini session outside any `chats` directory, **when** it is
   read with `--runtime gemini`, **then** it is not read and `errors` holds its path with `error`
   `OUTSIDE_CHATS`; `auto` reads it.
2. **Given** a root below a `chats` directory, **when** it is read with `--runtime gemini`,
   **then** each Gemini session in it is noted the same way.
3. **Given** a mixed root, **when** it is read both ways, **then** every Gemini file `auto` reads
   is either read by `--runtime gemini` or noted in its `errors`, and no other file is noted.
4. **Given** the shipped corpus, **then** `--runtime gemini` reads three sessions and notes
   `gemini-writes.jsonl`; `auto` reads all four with empty `errors`.
5. **Given** no root, or another runtime, **then** nothing is noted as `OUTSIDE_CHATS`.
6. **Given** a file that cannot be opened, **when** a root holding it is read with `auto`,
   **then** it lands in `errors` with its path, as it already did under `--runtime gemini`.

## Design

The issue's second option: keep each path's rule and report what one sets aside.
`--runtime gemini` under a named root still reads only files below a `chats` directory at or under
the root (RP-S019 decisions 5 and 12). Each `.jsonl` there outside `chats` whose first line `auto`
gives Gemini is noted in `errors` as `{"path": ..., "error": OUTSIDE_CHATS}` when the walk starts,
in path order, so `ruleprobe report` names it among the transcripts that produced no session.
Under `auto`, a file `_detect` cannot open goes to the Claude Code reader, the fallback, so its
read fails into `errors` instead of the file being dropped.

Rejected, each tried on this branch:

- `--runtime gemini` taking `auto`'s first-line rule alone dropped a `chats` file with a blank or
  malformed first line, and the legacy `.json` beside it (review round 1).
- `--runtime gemini` reading `chats` plus every Gemini-shaped file elsewhere double-counted a
  subagent copied outside `chats`, whose id loses its parent prefix and so groups apart from the
  original, and made a named `--root ~/.gemini/tmp` read files the default location does not
  (review round 2). Both break under-count-rather-than-over-count.
- Narrowing `auto` to `chats` would drop a Gemini session a user copied into a folder of their
  own, and the corpus's `gemini-writes.jsonl` with it.

`OUTSIDE_CHATS` sits beside `COPY` in `ruleprobe.readers` but is not added to `__all__` or the
README's public API: it is an `error` string like "no session in it".

## Regression test

`tests/test_reader_gemini.py`: `RootWalkTests`' two `chats`-rule tests now also assert the
`errors` note; new tests cover the mixed root, the shipped corpus, no note without a root or
under another runtime, a `chats` file with a malformed first line, and a legacy `.json` beside
one. `ErrorTests`' unreadable-file test runs both ways. Five fail on `0441f58` and pass after.

## Review findings

Round 1 (isolated reviewer, on `432c18e`):

1. Fixed: `--runtime gemini` gated on first-line detection and silently dropped a `chats` file
   with a blank or malformed first line. It now reads everything below `chats` as before.
2. Fixed: a legacy `.json` beside such a `.jsonl` was read by neither path; the `.jsonl` is read.
3. Fixed: the changelog claimed one rule for a root below `chats`; it now states each path's rule.
4. Kept: under `--runtime gemini` an unopenable `.jsonl` outside `chats` lands in `errors` though
   it may be another runtime's. Its runtime cannot be known, and an unknown failure is reported
   rather than dropped.
5. Out of scope: an unopenable file is reported as "no session in it", in every reader (Dev notes).
6. Noted: the mixed-root test guards the equality and passed on the base; the malformed-first-line
   test now covers what it could not.

Round 2 (isolated reviewer, on `840a0a6`):

1. Fixed by changing design: reading Gemini files outside `chats` double-counted a copied
   subagent. `--runtime gemini` reads `chats` only again and notes the rest in `errors`.
2. Fixed by the same change: a named `--root ~/.gemini/tmp` reads what the default location does.
3. Fixed: the unopenable-file case outside `chats` no longer arises under `--runtime gemini`.
4. Fixed: decision 5 holds again, and the below-`chats` test asserts the set-aside note.
5. Fixed: the docstring and changelog state each path's rule.
