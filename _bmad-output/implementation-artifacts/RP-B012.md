# RP-B012 — fix(readers): --runtime gemini and auto read the same Gemini files under a root

## Reproduction

Over the shipped corpus, `iter_sessions(root="ruleprobe/corpus/sessions")` reads four Gemini
sessions and `iter_sessions(..., runtime="gemini")` reads three, both with empty `errors`:
`gemini-writes.jsonl` sits outside any `chats` directory, so only `auto` reads it (Epic 5's
retrospective, finding F5). A synthetic tree with one session under `proj/chats/` and a copy
outside `chats` gives the same split.

## Root cause

`readers._paths` took two rules under a named root. `--runtime gemini` listed through
`gemini.transcripts(base)`, which keeps only files below a `chats` directory at or under the root
(RP-S019 decisions 5 and 12). `auto` walks every `.jsonl` and decides each by its first line
through `_detect`, so a Gemini-shaped file anywhere is Gemini's. Neither path records what the
other reads and it skips. `_detect` also returns `None` for a file it cannot open, and `_paths`
dropped that file under `auto`, so an unreadable file vanished there too.

## Acceptance criteria

1. **Given** a named root holding a Gemini session outside any `chats` directory, **when** it is
   read with `--runtime gemini` and with `auto`, **then** both read it.
2. **Given** a root below a `chats` directory, **when** it is read both ways, **then** both read the
   same sessions under the same ids.
3. **Given** a mixed root, **when** it is read both ways, **then** the Gemini sessions `--runtime
   gemini` yields are exactly the ones `auto` yields as Gemini.
4. **Given** the shipped corpus, **when** it is read both ways, **then** both read the same four
   Gemini files, `gemini-writes.jsonl` among them, with empty `errors`.
5. **Given** a file that cannot be opened, **when** a root holding it is read with `--runtime
   gemini` or `auto`, **then** it lands in `errors` with its path.
6. **Given** a file below `chats` whose first line is not Gemini's, **when** it is read both ways,
   **then** `--runtime gemini` reads it as before and `auto` yields it or records it in `errors`.

## Design

`--runtime gemini` keeps its layout rule and adds `auto`'s: under a named root it reads every
file below a `chats` directory at or under the root, legacy `session-*.json` included, and every
`.jsonl` whose first line `gemini.recognises`, wherever it sits. A `.jsonl` it cannot open is of
no known runtime and is read anyway, so its failure lands in `errors`; under `auto` such a file
goes to the Claude Code reader, the fallback, for the same reason.

So every file `auto` gives Gemini, `--runtime gemini` reads. A file below `chats` whose first line
is not Gemini's is read by both, as Gemini by one and by its detected runtime by the other, and
either way it yields a session or an `errors` entry.

Rejected: narrowing `auto` to `chats` would drop a Gemini session a user copied into a folder of
their own, and the corpus's `gemini-writes.jsonl` with it. Taking `auto`'s rule alone for
`--runtime gemini` (the first push) silently dropped a `chats` file with a blank or malformed first
line, and the legacy `.json` beside such a file, which review round 1 found.

Unchanged: the default location, read with no root, still lists `~/.gemini/tmp/*/chats/` only
(RP-S019 decision 5), since other files live under `~/.gemini/tmp`.

## Review findings

Round 1 (isolated reviewer, on `432c18e`):

1. Fixed: `--runtime gemini` gated on first-line detection and silently dropped a `chats` file
   with a blank or malformed first line. It now reads everything below `chats` as before.
2. Fixed: a legacy `.json` beside such a `.jsonl` was read by neither path; the `.jsonl` is read.
3. Fixed: the changelog claimed one rule for a root below `chats`; it now states each path's rule.
4. Kept: under `--runtime gemini` an unopenable `.jsonl` outside `chats` lands in `errors` though
   it may be another runtime's. Its runtime cannot be known, and an unknown failure is reported
   rather than dropped.
5. Out of scope: an unopenable file is reported as "no session in it", in every reader (Dev notes).
6. Noted: the mixed-root test guards the equality and passed on the base; the malformed-first-line
   test now covers what it could not.
