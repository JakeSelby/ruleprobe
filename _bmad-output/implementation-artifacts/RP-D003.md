# RP-D003 — decision(contract): whether a 0.x minor may break again after 0.2.0

## Context

FR-31 states the policy within a minor series: no declared name, call shape, row schema or entry
schema changes incompatibly. It leaves open whether a later 0.x minor, such as 0.3, may break the
declared surface again (PRD Q12). Maintainer decision 4 takes the break once, in 0.2.0. Common 0.x
practice lets a minor break. A downstream tool pinning 0.2, agent-harness first, needs to know what a
0.3 pin can do to it, and a ruleprobe release means a harness version bump.

## Options

1. **A later 0.x minor may break, with notice.** The case for: keeps room to fix the contract while
   the package is pre-1.0, as 0.x usually allows. The case against: every minor bump is a possible
   break for the harness, so each needs a contract test re-run and a changelog read.
2. **No further break before 1.0.** The case for: matches "taken once" literally and gives the
   strongest pin. The case against: a real contract fix waits for 1.0 or ships as an additive
   workaround.
3. **A later minor may break only what the fold map and schema version can absorb.** The case for:
   stored rows and renamed ids keep working. The case against: import names and call shapes have no
   such absorber, so the rule does not cover them.

## Decision

Decided 2026-09-23 by the maintainer: a later 0.x minor may break the declared surface, with notice.
Its changelog section opens with a Breaking heading naming the migration, and the contract test is
updated in the same change. This keeps room to fix the contract while the package is pre-1.0.

## Consequences

- Story 1.9 writes the rule into the README beside FR-31: no break within a minor series; a later
  0.x minor may break, and owes the Breaking heading and the updated contract test.
- The harness treats each minor bump as a possible break: it re-runs the contract test and reads the
  changelog's Breaking section before bumping.
