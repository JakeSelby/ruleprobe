# RP-E008 — Epic 6: agent-harness pins 0.2.0

- **Primary parent:** None

## Goal

Ship ruleprobe 0.2.0 so agent-harness can bump its pin with no code change. Done is observable: the
harness import surface is re-derived from harness `main` on release day, the contract test is updated
and green in the same change, the changelog names the 0.2 break, and the release workflow publishes
the wheel for the harness to vendor. Status: planned (v0.2.0).

## Scope and requirement coverage

In scope:

- The success targets and window the release is judged against (PRD §9, SM-1 to SM-8; PRD Q6).
- Re-deriving the harness surface and updating the contract test: FR-30 Declared public API.
- Cutting the version section that names the break: FR-31 Versioning policy.
- The release itself through `scripts/release_preflight.py` and the release workflow.

Out of scope: the features the release carries. They are delivered by Epics 1 to 5; this epic only
releases them.

## Children

In delivery order:

1. RP-D010 (#57): decision(release): the success targets and window for 0.2.0. Decided 2026-09-23:
   targets kept; the window is six months from the 0.2.0 release.
2. RP-T004 (#58): chore(release): re-derive the harness surface and cut 0.2.0.

## Architecture slice

- AD-9 The contract is versioned, once, in 0.2.0: the declared API is one contract test module,
  re-derived from agent-harness `main` before each release; the wheel is pure Python, carries
  `corpus/` and imports from a zip.
- AD-8 The package envelope: `dependencies = []` must still hold in the released wheel.
- agent-harness AD-13: the harness vendors a pinned wheel, never forks detector logic, and a ruleprobe
  release means a harness version bump.

## Sequencing

RP-D010 has no dependency and can be decided at any time before the release. RP-T004 runs last: it
depends on every in-scope item in Epics 1 to 5, on RP-D010, and on story 4.3, which the maintainer
confirmed on 2026-09-23. Nothing in RP-T004 runs in parallel with feature work, because the re-derivation
must read harness `main` on the release day.

## Exit criteria

- RP-D010 records each SM target and the window as kept or changed.
- The contract test matches harness `main` on the release day and passes; the harness commit read is
  recorded.
- `CHANGELOG.md` has a 0.2.0 section that names the break.
- `scripts/release_preflight.py` is clean in a fresh clone and the release workflow has published the
  wheel.
