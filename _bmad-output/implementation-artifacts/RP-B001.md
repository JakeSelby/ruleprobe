## Reproduction

From #19, at `91ce821`: a declarative detector using `not` or `absent` over `command`, fed a Bash
command the shell parse skipped.

- Inputs: `"pytest -q -k " + "x" * MAX_COMMAND` (over-long) and `"pytest -q -k 'foo"` (unbalanced
  quote), with `uv` and `pytest` variants.
- Observed for all four cases: `skipped=True`, `not` fires, `absent` fires.
- `absent` of `git push` also fires on ``git push origin 'main``.
- A `command` block holding only `regex` is not affected.

Scope per #19: no shipped detector uses `not` or `absent`, so the six shipped detectors and
agent-harness's Python detectors are unaffected; user-written declarative detectors are exposed.

The 2026-09-23 amendment on #19 widens the scope to AD-4 in full: `env` keys over a skipped command,
three-valued `any` and `all`, `order` with an undecided endpoint, and a detector whose whole `when` is
undecided.

## Root cause

`Parsed.__init__` in `ruleprobe/shell.py` sets `skipped` for a command that is empty, longer than
`MAX_COMMAND` (16 KiB), fails to tokenize, or raises during parsing, and leaves `pipelines` empty. The
segment matchers in `ruleprobe/matchers.py` then return `False`, not "undecided":

- `_m_command.match` loops over `parsed.pipelines`, finds none, and returns `False` when any
  per-segment key is set.
- `_m_git.match` iterates `git_calls(parsed, subs)`, finds none, and returns `False`.
- `_m_env.match` loops over `parsed.pipelines` and returns `False`.

The combinators are two-valued: `_m_not` returns `not part(event, env)`, so `False` becomes a match;
`_m_any` and `_m_all` use Python `any` and `all`. `_a_absent.run` counts a scope as a hit when no
event matches `of`, so a `False` from a skipped command reads as "never happened". `_a_order.run`
needs `first` and `then` true, so it does not over-count today, but it has no undecided state to pass
through. This breaks NFR-4 and AD-4's rule that undecidable input yields no hit.

## Acceptance criteria

Each is a regression test over a command the shell parse skipped, as `Parsed.skipped` marks it.

1. **Given** #19's "Done when", **when** the story closes, **then** every item of it holds.
2. **Given** each `env` key, **when** it matches a skipped command, **then** it returns undecided, as
   the `command` and `git` segment matchers do; **and** `command.regex` and `command.unparsed` are
   exempt and keep their 0.1.0 result.
3. **Given** `not` over an undecided matcher, **when** evaluated, **then** it is undecided, never true.
4. **Given** `any`, **when** evaluated, **then** it is true on any true child, else undecided on any
   undecided child, else false; one test per branch.
5. **Given** `all`, **when** evaluated, **then** it is false on any false child, else undecided on any
   undecided child, else true; one test per branch.
6. **Given** a `when` that evaluates to undecided, **when** the detector runs, **then** it produces no
   hit.
7. **Given** an `order` detector, **when** `first` or `then` is undecided, **then** it produces no hit;
   a hit needs both true.
8. **Given** an `absent` scope holding an undecided candidate and no true one, **when** the detector
   runs, **then** it produces no hit, for `scope: turn` and `scope: session` both.
9. **Given** every shipped declarative detector, **when** `tests/test_equivalence.py` and `ruleprobe
   corpus --floor 0.9` run, **then** both still pass.

## Design

Per AD-4: every `command` key except `regex` and `unparsed`, every `git` key and every `env` key is a
segment matcher, and over a skipped parse it returns undecided. `any`, `all` and `not` pass undecided
through with the truth table in AC 3 to 5. A `when` that is undecided produces no hit; `not`,
`absent` and `order` treat undecided as no hit.

A `text` read of `source: heredocs` is undecided over a skipped parse too: the parse is what finds
heredoc bodies, so none found there is not none present. AD-4's first rule, that undecidable input
yields no hit, already covers it, so the spine's list of segment keys is not amended; the
`ruleprobe/matchers.py` docstring, the contract reference, names it. `payload`, `command` and
`assistant` text reads keep their answers.

The fix must not change: results for a parsed command; `command.regex` and `command.unparsed`;
the shipped detectors' hits (AC 9). It changes counts for user detector files that use `not` or
`absent`, so it ships inside the 0.2 break (AD-9) and is named in `CHANGELOG.md`. It lands before
story 2.4, whose compiled opportunities read undecided through these combinators. [ASSUMPTION: the
representation of undecided (for example a sentinel or `None`) is left to the implementer; the corpus
fixes only its semantics]

## Dev agent record

  that asks only "did it match" reads it as no match; `not`, `any`, `all` and the implicit `all` of a
  multi-key mapping apply the Kleene truth tables in AC 3 to 5.
- **Segment matchers:** `command` returns undecided over `Parsed.skipped` only after `unparsed` and
  `regex` have held, so a decided `regex` or `unparsed` still settles the block; `git` and `env`

## Review findings

`bmad-build` review, three layers (blind hunter, edge-case hunter, verification gap; the last found
no gap). Every patch went back to the builder and was verified on the full gate afterwards.

- **Patched, medium:** `text` with `source: heredocs` still returned a decided false over a skipped
  parse, so `not` or `absent` over it counted an unreadable command (both hunters). Now undecided,
  with a paired test that fails against the first fix.
- **Patched, medium:** "negate one only through `not`" gave a Python caller holding a
  `compile_matcher` predicate no usable rule. The changelog and both docstrings now say that a
  caller who negates a predicate itself reads undecided as false and should compose through the
  declarative `not`, `any` and `all`. Whether to export an `is_undecided` helper is new public
  surface, raised with the maintainer for #35.
- **Patched, low:** tests for a `regex` that holds beside a segment key, positive controls for the
  undecided `when` and the `order` `first` case, the empty command, and `h.turn` for `h[1]`.
- **Patched, low:** the README's detector guide now says what undecided means for `not` and `absent`;
  `epics.md` FR-12 and NFR-4 match the PRD's status; the PRD line and the docstring are rewrapped;
  a stray blank line is gone.
- **Patched, low:** AC 9 had no recorded evidence; the gate output is recorded below.
- **Rejected, false:** "`### Breaking` is not a Keep a Changelog category". `docs/releasing.md` and
  AD-9 prescribe a Breaking heading for a break.

`bmad-code-review`, four layers (blind hunter, edge-case hunter, verification gap, acceptance
auditor; the verification gap found none):

- **Patched, medium:** the README said a session-scope `absent` loses a hit only when the test run
  itself was skipped; any one skipped Bash command in the session makes it undecided. Fixed, and it
  says `command: {unparsed: true}` matches such commands on its own.
- **Patched, low:** the docs described a skipped parse as "empty, over 16 KiB, or one that does not
  tokenize"; `Parsed` also skips a missing or non-string command and one whose parse raises, and
  `MAX_COMMAND` counts 16,384 characters, not bytes. The docstring, README and changelog say so.
- **Patched, low:** three undecided tests lacked the parsed control the class promises; `payload` and
  `command` text reads are now pinned as decided; a bare `git` and `env` `when` are covered (AC 6).
- **Patched, low:** the record now carries the gate output and the red-before count, and the file list
  is complete.
- **Deferred, low:** AD-4's list of undecided reads names only the `command`, `git` and `env` keys; the
  heredocs text read belongs there too. The fix edits the spine, so it goes through `bmad-architecture`
  update intent, suggested with #36; logged in `deferred-work.md`.
- **Deferred, low, pre-existing:** `command: {unparsed: true}` beside a segment key never fires and
  raises no error, as in 0.1.0. A spec-time error would change the AD-7 vocabulary; logged.
- **Rejected, by design:** "treat an empty or missing command as decided". AD-4 names a missing field
  and an empty command as undecidable input.
- **Rejected:** "epics status, memlog lines and the Python-caller note were not asked for". Each
  answers a recorded review finding or #19's "Done when".
