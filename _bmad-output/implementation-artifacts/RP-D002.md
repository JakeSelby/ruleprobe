# RP-D002 — decision(api): whether root __all__ names outside FR-30 join the declared API

<!-- bmad-sync:begin -->
- **GitHub issue:** [#30](https://github.com/JakeSelby/ruleprobe/issues/30)
- **Primary parent:** [RP-E003](https://github.com/JakeSelby/ruleprobe/issues/22)
- **State:** active

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Context

FR-30 declares the public API: the README's eight 0.1.0 names plus every name agent-harness imports.
The root `__all__` in `ruleprobe/__init__.py` exports more than that, for example `measure`,
`load_corpus`, `Bundle`, `from_spec`, `register_compiler` and `score_examples`. PRD Q8 asks whether
those names join the declared API or stay importable and undeclared. The answer blocks FR-30 and
FR-31, since a declared name cannot change incompatibly within a minor series. AD-9 says a name joins
only with its test.

## Options

1. **Keep them importable and undeclared.** The case for: the promise stays as small as the known
   consumer needs; SM-4 (zero breakages) is easier to hold; names can still be declared later, one at a
   time, with a test. The case against: a downstream author who imports one today gets no promise, and
   nothing stops them importing it.
2. **Declare every root `__all__` name.** The case for: what is exported is what is promised, with no
   gap to explain. The case against: every such name needs a contract test in story 1.8, and each
   becomes frozen for the 0.2 series, including names nobody outside uses.
3. **Declare a named subset.** The case for: promises the names with a plausible outside use, such as
   `measure` for a tool storing rows. The case against: needs a per-name judgment the corpus does not
   yet record.

## Decision

Open: the maintainer's answer to PRD Q8, marking each name outside FR-30's list declared or
importable-undeclared. The corpus's working default is undeclared (option 1); SM-4's counter says the
list is not grown to avoid a break (epics.md story 1.2, tagged there as an assumption).

## Consequences

- **Option 1:** story 1.8 tests exactly FR-30's list; the README says other root names are importable
  but not covered by FR-31; they may change in a 0.2.x.
- **Option 2:** story 1.8 grows a test per extra name; story 1.9's policy covers all of `__all__`;
  removing any of them later is a break.
- **Option 3:** as option 2 for the chosen names, as option 1 for the rest; the README names both
  groups.
- Any option: a name marked declared has a contract test when story 1.8 lands.
