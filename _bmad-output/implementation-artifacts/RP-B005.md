# RP-B005 — fix(detectors): no-verify counts a hooksPath override only when it disables hooks

<!-- bmad-sync:begin -->

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. A synthetic Bash tool use: `git -c core.hooksPath=.githooks commit -m x`.
2. Run the shipped `verification/no-verify` over it, through `ruleprobe.run` or the corpus.
3. Observed on `46f3528`: one hit. The detector counted any token starting `core.hooksPath=`
   as a bypass, so a repository that turns its own tracked hooks on through `-c` scored as
   skipping them. In the field sample (#53), 5 of 6 distinct no-verify hits had this shape.

## Root cause

`no_verify` in `ruleprobe/detectors/common.py` matched `t.startswith("core.hooksPath=")`
over every token of the git segment, and its declarative twin in `common.yaml` and the
catalog restatement in `catalog.py` used `token_prefix: "core.hooksPath="`. Neither read the
value: `core.hooksPath` names the directory git runs hooks from, and only a path that holds
no hooks skips them. The prefix also matched a token after the subcommand, and missed a key
spelled in another case, which git accepts because config keys are case-insensitive.

## Acceptance criteria

1. **Given** `git -c core.hooksPath=.githooks commit -m x`, **when** `verification/no-verify`
   runs, **then** it gives no hit; the same holds for any other non-empty path but `/dev/null`.
2. **Given** `-c core.hooksPath=` (empty), `-c core.hooksPath=/dev/null`, their quoted forms
   and `-c core.hookspath=…` in any case, on a `commit` or `push`, **when** it runs, **then**
   it gives one hit.
3. **Given** the `--no-verify` or `-n` flag, or a `SKIP` or `PRE_COMMIT_ALLOW_NO_CONFIG`
   assignment, **when** it runs, **then** it fires as before, a tracked hooks path beside it
   included.
4. **Given** every case in AC 1 to 3, **when** the Python detector, its `common.yaml` twin and
   the catalog entry run, **then** they give the same hits (AD-7).
5. **Given** the corpus with a near-miss label for AC 1, **when**
   `ruleprobe corpus --no-config --floor 0.9` runs, **then** it passes with no false positive.

## Design

- Read only the value of each `-c` given before the subcommand, through a new
  `ruleprobe.shell.git_config(segment)`, and count it when it fully matches
  `(?i)^core\.hookspath=(?:/dev/null)?$`. The pattern lives once per surface: `_HOOKS_OFF` in
  `common.py`, and the same string in `common.yaml` and `catalog.py`.
- The declarative format had no way to say this: `token_prefix` is a case-sensitive prefix
  over the whole segment, and `arg_regex` reads only arguments after the subcommand. The fix
  adds one additive `git` key, `config_regex`, searched in each `-c` value before the
  subcommand, so the twin and the catalog stay hit-for-hit with the Python detector.
- Rejected: a `text` regex over the whole command beside a `git` block, which loses the
  segment scope and would fire on an `echo` of the override next to a plain commit, an
  over-count AD-4 forbids; and a `command.first_operand` regex, which sees only the first `-c`
  and cannot tie the override to a `commit` or `push`.
- A hooks path to an existing but empty directory also skips hooks and is not counted. That
  is the under-count AD-4 prefers: telling it apart needs the file system.
- Unchanged: the flag and assignment spellings, `token_prefix` itself, and the detector id,
  rule and event.

## Regression test

`tests/test_no_verify_hookspath.py`: `git -c core.hooksPath=.githooks commit -m 'feat(x): y'`
and four other non-disabling paths give no hit; seven disabling spellings give one; each case
through both the shipped detector and the `common.yaml` twin. The `.githooks` case fails on
`46f3528` and passes after. The corpus gains `4:tu-w7` in `verification-hooks.jsonl`, a
near-miss that was a false positive before. The catalog entry gains a `/dev/null` positive
and a `.githooks` negative in its `examples`.
