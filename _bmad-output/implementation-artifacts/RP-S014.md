## Story

As a developer with rules,
I want the share of my rules that are measured,
so that I can see how much of my file anything checks.

## Context and value

FR-14 is partial: 0.1.0 prints `rules: N measured, N dark, N unmeasured` from `Bundle.summary` in
`ruleprobe/rules.py` and no share. The agent-harness's FR-67 asks for the share. The share is also
what the rest of Epic 3 moves: section-level binding (RP-S015) and the catalog (RP-S016) raise it, so
it must exist before they land. Under `--json`, the coverage block is written to stderr today, not
into the JSON document (`ruleprobe/cli.py`, the `args.json` branch).

## Acceptance criteria

1. **Given** a rules directory with measured, dark and unmeasured rules, **when** `report --rules`
   runs, **then** the coverage block prints the three counts and the measured share.
2. **Given** zero rules, **when** it runs, **then** no share is printed and nothing divides by zero.
3. **Given** `--json`, **when** it runs, **then** the same counts and share appear in the output.
   [ASSUMPTION: the coverage block is carried in `--json`; today it goes to stderr only]

## Design

### Approach

Compute the share in `Bundle` beside `counts()`, as measured over all rules, and print it on the
`rules:` line of `summary()`. `rules.py` owns binding and counts; the report reads the `Bundle` and
never binds (AD-12). For `--json`, add the counts and share to the document from the same `Bundle`
method, so text and JSON never disagree. [ASSUMPTION: the share's denominator is all rules, dark
included, as FR-14 says "the share of rules measured"]

### Decisions and alternatives

- The share's print format is not fixed by the corpus. [ASSUMPTION: a percentage on the `rules:` line]
- Whether dark rules leave the denominator is not recorded in the corpus; see the assumption above.

### Do not implement

- Section-level splitting (RP-S015) or catalog binding (RP-S016).
- Any change to row schema or `report_data` beyond carrying the coverage counts.

### Completion notes

- `Bundle.coverage()` returns the three counts plus `share`, measured over all rules with dark
  ones in the denominator, and `None` for zero rules. `summary()` and `report --json` both read it.
- The `rules:` line appends `(N% measured)`. The percentage is floored with integer arithmetic,
  so 199 of 200 prints 99%, never 100%, following the package's under-count rule.
- `report --json` carries the dictionary under a top-level `coverage` key on every run. Without
  `--rules`, the counts are zero and `share` is `null`. The coverage block still goes to stderr
  as before. `schema_version` is unchanged because the key is additive.
- The tests are in a new `tests/test_coverage.py`, not in `test_rules.py` and `test_cli.py`, so
  they do not conflict with parallel edits to those files. The existing assertions in
  `test_rules.py` still pass unchanged because they use `assertIn`.
- After review: one helper derives the printed percent from `coverage()`'s own total. It prints
  `<1%` when the floor is 0 but a rule is measured. The README example line and the `coverage` key
  are documented, and a test ties the README `rules:` line to `summary()`.
