### Aggregate views

**Architecture delta.** One module joined the graph: `ruleprobe/contract_data.py`, a literal-only
leaf imported by `registry` alone (`6baa715`), and the spine's AD-1 graph was amended in the same
change (ARCHITECTURE-SPINE.md, "Amended 2026-09-23: `contract_data` joins the graph"). `matchers`
and `report` now import `SCHEMA_VERSION` and `KNOWN_SCHEMA_VERSIONS` from `registry`, and `rules`
imports `schema_version_error` from `matchers` (`5a7ef4c`, `c2bc203`). Every new edge points the way
AD-1 already allowed; no cycle was introduced. Checked by reading the import lines in the nine
commits; no dependency tool was run.

**Duplication map.**

- F1. "Is this a known schema version" is implemented twice: `schema_version_error` in
  `ruleprobe/matchers.py` for entries (`c2bc203`) and `_is_known_schema` in `ruleprobe/report.py`
  for rows (`5a7ef4c`). Both refuse booleans and read `KNOWN_SCHEMA_VERSIONS`, so they agree today;
  a third version or a new refusal rule must be made in both. *Instance:* accept. *Prevention:*
  none needed while the rule stays one line each; revisit when schema 3 is added.
- F2. A rename chain is followed in two places: `fold_map` in `ruleprobe/registry.py` and
  `_current` in `ruleprobe/report.py` (`6baa715`). The split is deliberate, and RP-S009's review
  records why (`folded_rules` must not merge the shipped map again). *Instance:* accept.

**Size growth.** `ruleprobe/matchers.py` grew from 809 to 991 lines across the envelope, 112 net of
it from Epic 1 (`5cc22ea`, `c2bc203`, `68bad42`); it is the largest module in the package.
`ruleprobe/report.py` grew from 257 to 308 lines within the envelope and is 828 lines at `ecacae5`,
mostly from Epics 2 and 4. Neither was read as a god class: `matchers.py` is one flat table of
matcher compilers. *Instance:* accept. *Prevention:* watch `report.py` in the Epic 2 and 4 retros.

**Pattern divergence.** None found. The new code follows the package's existing conventions:
`%`-formatting, a docstring that states the contract, findings with a file and a line, and
refusal of booleans as integers (as `arg_count` already did).

**Spec-to-implementation reconciliation.**

- F3. Entry `schema_version` is validated and then discarded. `compile_detector` refuses an unknown
  value (`ruleprobe/matchers.py`, `c2bc203`), but the compiled `Detector` does not carry the value,
  so a schema-1 entry runs under the 0.2 undecided rule exactly as a schema-2 entry does. The
  `CHANGELOG.md` Breaking section says this ("no edit is needed"), but the matchers docstring says an
  entry for a later schema "is refused rather than read under the wrong one", which a reader can
  take to mean schema 1 is read under schema-1 rules. *Instance:* fix now, docs only. *Prevention:*
  a decision item should say what a schema version *does*, not only what it is.
- F4. The spine still tags AD-9's package-data bullet `[ASSUMPTION: the module is

  tag in the same change.
- F5. Readiness findings L1, L4 and L8 are still open as `epics.md` open questions 17, 18 and 19. 17
  (FR-29: rows from `measure()` carry no fold map) and 18 (README checked against the contract list

### Diff-scope review (`bmad-review`: adversarial, edge-case, verification-gap)

Run inline, one lens after another, over the code part of the nine commits (`ruleprobe/`,
`scripts/`, `.github/`: 1,150 diff lines), because no subagents were available. Tests, docs and
story files were read to confirm findings, not reviewed as content. The boundaries between stories
were weighted, as the skill asks.

- F7 (adversarial). The series-contract check in `scripts/release_preflight.py` (`errors`, `if tag
  is not None and SEMVER.fullmatch(version)`) runs only on a release: a tag, or a pull request that
  changes `__version__`. An ordinary pull request that drops a name from `DECLARED` in
  `tests/test_contract.py`, and edits the README list to match, passes every check. The drop is then
  caught by the next patch release's pull request, not the one that caused it. *Instance:* fix now.
  *Prevention:* a guard should fire on the change that breaks it, not on the next release.
- F8 (adversarial). The same check compares only `(module, name)` pairs. FR-31 and the README's
  Versioning section also promise call shapes, the row schema and the entry schema within a minor
  series. A patch that keeps every name but changes a call-shape assertion in
  `tests/test_contract.py` passes. Story 1.9 AC4 asked for names only, so this is a spec gap, not a
  build defect. *Instance:* defer to the maintainer. *Prevention:* spec wording.
- F9 (adversarial). Decision 1.3 lets a later 0.x minor break the declared surface "with notice: its
  changelog section opens with a Breaking heading". Nothing checks this: `contract_errors` skips
  every `X.Y.0` (`series_tag` returns `None`). *Instance:* fix now; a small preflight addition.
- F10 (edge case). `release_tag` in `scripts/release_preflight.py` calls
  `package_version(init=base_init)`, which raises `ValueError` when the base file declares no
  `__version__`. `main` does not catch it, so CI shows a traceback instead of a `release error:`
  line. It fails closed. *Instance:* accept, or fold into F7's change.
- F11 (edge case). `_not3`, `_any3` and `_all3` in `ruleprobe/matchers.py` test undecided by
  identity (`is _UNDECIDED`), but the declared `is_undecided` uses `isinstance`. RP-S010's review made
  that change so that a copied value still reads as undecided. A copied undecided value passed back
  into a declarative combinator would be read as decided-false. Nothing in the package copies one
  today. *Instance:* accept. *Prevention:* none.
- F12 (adversarial). The package envelope's import scan and run-time guard miss `ssl`, `smtplib`,
  `os.system` and similar. **Deferred (logged)** from RP-T002's review; widening AD-8's list is the
  maintainer's call.
- F13 (adversarial). A report over rows from both sides of the break sums schema-1 and schema-2 rows
  silently. **Deferred (logged)** from RP-S008.
- F14 (adversarial). A consumer detector registered under an id that a shipped rename retires loses
  its report line. **Deferred (logged)** from RP-S009.
- F15 (adversarial). The `## Gate` block in `AGENTS.md` does not name the `--base-init` preflight
  step that CI's `test` job now runs (`af3bcaf`). **Deferred (logged)** from RP-C004 "when
  `AGENTS.md` is next edited"; still unapplied at `ecacae5`. *Instance:* fix now; it is a one-line
  doc change and it keeps getting skipped.
- Verification gap: **No verification gaps found.** Checked: the undecided truth table
  (`tests/test_matchers.py`), the schema-version cases for entries and rows
  (`tests/test_schema_version.py`, `tests/test_report.py`), the shipped fold map under

### Process lessons (from story-file review records)

- F16. Two review passes per story, a `bmad-build` review and then a `bmad-code-review`, caught
  tests that could not fail: the root-name test compared each name with itself (RP-S010), the
  file-read trace patched `io` names the import system never calls (RP-S009), and the wheel-name
  check passed on a name the test chose itself (RP-S010). A contract or envelope test that cannot
  fail is worse than none, because it reads as a guarantee. RP-B002 already records a red-before
  run and a mutant for its claims. *Prevention:* make that a required dev-note line for contract,
  envelope and gate tests.
- F17. The release preflight added in #7 refused every pull request that added an `## Unreleased`
  entry, so the first 0.2 pull request broke on it (#64). Its fix made the refusal release-only,
  which opened the gap #68 closed. A gate was shipped without a test of the ordinary pull-request
  path. *Prevention:* a new gate ships with a test of the common pass case as well as the refusal.
- F18. `scripts/bmad_issue_sync.py` records an issue closed as not planned as `completed`, so #28,
  #59 and #60 (Epic 7, withdrawn) read as `completed`. The generated sprint status therefore shows
  `epic-7: done`. **Deferred (logged)** from the refresh for RP-B002.
