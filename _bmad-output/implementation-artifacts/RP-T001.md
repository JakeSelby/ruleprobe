## Goal

State the versioning policy and the 0.2 break where a downstream tool author will read them, so they
know what a 0.2.x bump can and cannot do. FR-31 has no written form in 0.1.0, and `CHANGELOG.md` must
name the break before the tag. Depends on RP-D003 (#31) and RP-S010 (#35).

## Acceptance criteria

1. **Given** the README, **when** read, **then** it states that within a minor series no declared
   name, call shape, row schema or entry schema changes incompatibly, and states the RP-D003 decision.
2. **Given** `CHANGELOG.md` Unreleased, **when** read, **then** it names each part of the break:
   schema versions, persisted fold map, declared API, the undecided rule (#19), and the result-shape
   change of the coverage block moving from stderr into `--json` output (story 3.3; today
   `ruleprobe/cli.py` writes it to stderr).
3. **Given** a detector rename in a 0.2.x change, **when** the suite runs without a fold entry,
   **then** RP-S009's shipped-id test fails.
4. **Given** a 0.2.x release candidate, **when** `scripts/release_preflight.py` runs, **then** it fails
   if the contract test drops a name the v0.2.0 tag declared. [ASSUMPTION: a preflight check is the
   mechanism for "a 0.2.x passes the 0.2.0 contract test unchanged"]

### Completion notes

- **AC 1.** The README gains a `## Versioning` section after the public API: what 0.2.0 versions
  (declared API, row schema, detector-entry schema), no incompatible change within a minor series,
  RP-D003's decision (a later 0.x minor may break with a Breaking heading and the contract test
  updated in the same change; a pinning tool treats each minor bump as a possible break), and a
  break is a major from 1.0. It sits outside `## The public API`, so the contract test's README
  parse is unchanged.
- **AC 2.** Each part already had its own `### Breaking` bullet (undecided rule #19, schema
  versions #32, fold map #34, declared API #35, coverage block in `--json` #47, section rules
  #48). A lead paragraph under `### Breaking` names all six as the one 0.2 break and points at the
  README policy; no bullet is duplicated.
- **AC 3.** Confirmed by mutation in a scratch copy, not by a new test: renaming
  `transcript-hygiene/whole-file-cat` in `ruleprobe/detectors/common.py` with no fold entry fails
  `test_every_shipped_id_is_registered_or_folded` (and two neighbours); adding the `RENAMED` entry
  clears it, leaving only `test_every_default_detector_is_on_the_shipped_list` until the new id
  joins `SHIPPED_IDS`, which is the documented rename procedure.
- **AC 4, design.** `scripts/release_preflight.py` gains `contract_errors`: when checking as a
  release (`--tag`, or `--base-init` with a changed version) of `X.Y.Z` with `Z > 0`, it reads the
  `DECLARED` literal from `tests/test_contract.py` at `refs/tags/vX.Y.0` with `git show`, parses it
  with `ast` (no import), and reports every `(module, name)` pair missing from the tree's
  `DECLARED`. A name moved to another module counts as dropped. Choices made:
  - Generalised from "v0.2.0" to each series' `.0` tag, which is FR-31's rule; 0.1 patches are
    exempt because v0.1.0 carries no contract test.
  - Fails closed: an unreadable tag or a file with no `DECLARED` dict literal is an error.
  - Release mode only, not every CI run: between releases a drop is caught at the release PR.
  - Names only, as the AC asks; call shapes stay the contract test's job.
- **CI wiring is not in this change.** `ci.yml` checks out with `fetch-depth: 2` and `release.yml`
  with the default depth, so neither has the series tag; the first 0.2.x patch release would fail
  the preflight with "cannot read" until both fetch it. Nothing fails before then: 0.2.0 opens its
  series and is not checked.
- 2026-09-23: the architecture spine was amended on this branch through `bmad-architecture` update
  intent (commit "docs(architecture): amend AD-4 heredoc reads and AD-12 file rule names"). AD-4 now
  names a `text` read of `source: heredocs` among the reads that are undecided over a command the
  shell parse skipped, as `ruleprobe/matchers.py` already did. This was deferred from the review of
  #19 (RP-B001), which found the spine listing only the `command`, `git` and `env` keys.
- 2026-09-23: the same amendment made AD-12 name a file bound in its front matter by its `rule:`
  key, else its file name without extension, as `ruleprobe/rules.py` has done since 0.1.0. The
  build of #48 (RP-S015) found the spine's path-relative-to-`--rules` wording contradicting the code.
  The update logged an open question, now in `deferred-work.md`: two rule files with the same name
  in different directories under `--rules` get one rule name, and nothing reports it.
