## Story

As the maintainer and every future builder of ruleprobe, I want a PRD that states the package
contract, the bounded claim and the 0.2 requirements with testable consequences, so that stories
bind to FR ids and the spine binds its decisions to them.

## Context and value

The product brief set the position: an engine, not a doctor. The PRD turns it into requirements a
story can be accepted against. It also declares, for the first time, the surface agent-harness
actually depends on, which is far wider than the README's eight names. An undeclared surface is
how a vendored consumer breaks silently.

## Acceptance criteria

1. **Given** the brief, research and code, **when** `bmad-prd` runs, **then** `prd.md`,
   `addendum.md` and a memlog exist under `_bmad-output/planning-artifacts/prds/prd-ruleprobe-2026-09-23/`, with FR, NFR and SM ids.
2. **Given** each FR, **when** it is read, **then** it carries a status label that matches the code
   and testable consequences covering its operative clauses.
3. **Given** FR-30, **when** its contract test is written, **then** the test exercises every name,
   call shape and non-import dependency agent-harness uses today, re-derived from harness `main`.
4. **Given** the maintainer's decisions, **when** the PRD is read, **then** none is re-decided and
   no doctor feature appears: no prescription, cause triage, blocking hook or model call in `report`.
5. **Given** a fresh-context validation, **when** it reports findings, **then** each is applied
   through the update intent and logged.
6. **Given** the configured `doc_standards`, **when** the structure and prose lenses run, **then**
   their findings are applied with no requirement renumbered or changed in meaning.

## Design

### Approach

Headless Fast path from the brief, research, code and the agent-harness corpus, with the
maintainer's decisions as binding rules. Essential spine plus the developer-products and
cross-cutting clusters. Then validation, update and polish, each in its own context.

### Decisions and alternatives

- **FR-30 is re-derived from harness source, not from notes.** The first draft's list came from
  the harness source at a pinned commit; the validation found call shapes still missing, including
  the detector function signature and its context attributes, and the update added each with a
  file reference.
- **Explain covers transcripts, not stored rows.** A row keeps counts only; widening it to carry
  hits was rejected. For a stored row the explain path names the re-run that would explain it.
- **Redaction before printing or labelling.** FR-25 and FR-26 redact with the shipped secret
  patterns before any text leaves the transcript.
- **`promote?` is left to the maintainer** as an open question with a recommendation (neutral
  wording, no advice), because it touches the "prescribes nothing" decision.
- **No personal measurement is published.** The draft's session count from the maintainer's own
  machine was removed pending the maintainer's decision.

### Do not implement

- The spine or the stories; each has its own issue.
- The README miscount the validation found; it is an open question for the 0.2 stories.
