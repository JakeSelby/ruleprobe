## Story

As a developer whose rules mention compaction, model switching, secrets or `find`,
I want those rules bound to the shipped detectors,
so that the defaults measure my own rules.

## Context and value

The 0.2 catalog holds seven shapes, and four of the six shipped default detectors have none:
`cache-hygiene/compact`, `cache-hygiene/model-switch`, `secrets/secret-in-write` and
`transcript-hygiene/unfiltered-find`. A rule about any of them is never bound, so the one
detector already measuring the observable never measures the rule. RP-SP004 found 9 of the
per-sentence prototype's 11 zoo misses were catalog phrasings, and moved the 0.70 recall bar from
the binder to Epic 8 as a whole; the zoo's four labels for these detectors were counted apart as
"no catalog entry binds yet". Story 8.3 (#141, RP-S022) shipped per-sentence binding in #142 under
variant S (an exception or permission anywhere in a section unbinds every rule in it), at 0.65.

## Acceptance criteria

1. **Given** a rule sentence in the shape of each of `compact`, `model-switch`,
   `secret-in-write` and `unfiltered-find`, **when** it binds, **then** it binds that detector,
   catalog-bound, and the shipped detector measures it.
2. **Given** a near-miss sentence for each (an exception, a condition, a permission, a mention, a
   narrowing, a neighbouring topic), **when** it binds, **then** it stays unbound.
3. **Given** `secret-in-write` outside the defaults (Epic 9), **when** its rule binds, **then** the
   coverage block says which detector it bound and that the detector is not a default.
   **Deferred to Epic 9** (see Decisions, 4).
4. **Given** the rules zoo with positives and near-misses for the four shapes, **when** `corpus`
   runs, **then** it shows zero false binds, recall of at least 0.65, and the recall floor keyed to
   the new zoo's sha256 at the recall measured.

## Design

### Approach

- Four entries appended to `catalog.ENTRIES`, after the seven, so every existing coverage line
  and catalog order is unchanged. Each `detector` restates the shipped one under its id: its
  `when` equals `common.yaml`'s twin, and `Bundle.registry` keeps the `DEFAULT` detector in place,
  as for `no-verify` and `whole-file-cat`. Each carries `examples:` with a near-miss beside each
  positive, scored against both the catalog twin and the shipped detector.
- Patterns, all anchored and clause-bounded:
  - `compact`: never, do not or avoid (running or using) `/compact`, compact or compacting,
    optionally "the context, conversation or session", or "start a fresh session rather than
    compacting"; then an optional mid-task, mid-session or "in the middle of" scope.
  - `model-switch`: never or do not switch, change or swap (the) model(s), or stay or stick with
    one model for the whole session or conversation; the same optional scope.
  - `secret-in-write`: never write, hardcode, paste, put, embed or inline a secret, credential,
    API or access key or token, or private key; optionally in or into a file, source, code, config,
    script or disk.
  - `unfiltered-find`: filter or narrow every `find`, or never run an unfiltered, bare or unbounded
    `find`.
- The first three end at a clause break or the sentence's end, through a lookahead
  `(?=\s*[.!?;,:–—]|\s*$|\s+-+\s)`. A rule narrowing them ("never compact more than once", "never
  switch models to save money", "never paste a secret into the chat") then binds nothing.
- Zoo: 40 new items (`k`, `n`, `w`, `u`), 12 positives and 28 near-misses; no existing label
  changed. The `about` text now says which items came with this story. The floor is re-keyed.

### Decisions and alternatives

1. **End-anchored patterns for the three session and write shapes.** Their detectors count every
   compaction, every model change, every secret-shaped write, so a rule with a trailing qualifier
   the pattern cannot read would be measured against events it permits. Rejected: prefix-only
   patterns like the seven, which bound "Never compact more than once per session" to a detector
   counting the first compaction. `unfiltered-find` stays prefix-only because its positives carry
   how to filter ("by name or depth"), which never narrows the rule.
2. **`secret-in-write` names destinations, and passwords are not an object.** "Never paste a secret
   into the chat" is not a write the detector sees, and no pattern in the detector finds a password.
   Rejected: any object after the verb, which binds both.
3. **Timing words scope to task as well as session.** The frozen zoo labels "Never switch models in
   the middle of a task" and "Do not run /compact mid-task" positive; RP-SP004 froze those labels,
   so the patterns read them. "Stick with one model per task" stays unbound: a session spans tasks.
4. **AC3 deferred to Epic 9.** The generic reading, "a catalog-bound detector not in the base
   registry's default set says so", is two lines in `Bundle.summary`, but five catalog-only
   detectors (`test-after-change`, `force-push-default`, `pip-install`,
   `non-conventional-subject`, `secret-file-add`) are already outside `DEFAULT`, so it would change
   every existing catalog-bound line. Whether those count as "not a default" is a product call on
   what the default set means, which Epic 9 story 9.5 makes when it defines the set by NFR-10.
   Until then `secret-in-write` is a default and the note would print nowhere.
5. **Catalog size.** FR-16 and the spine recorded "a small set of six to eight shapes" for 0.2; the
   catalog now holds eleven, as story 8.4 plans. The size test asserts eleven, and PRD FR-16, its
   open question 3 and spine AD-12 carry dated amendments, the 0.2 lines kept as written.

### Do not implement

- Wider phrasings for the seven 0.2 entries (a separate story).
- Any change to an existing zoo label, or a looser false-bind gate.
- A change to the binder, its exception or condition words, or `DEFAULT`.
