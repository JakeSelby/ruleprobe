## Story

As a downstream tool with a ledger written under an older release,
I want renamed detector ids to fold without my process having built the registry,
so that a rename never drops my history.

## Context and value

FR-29 is partial in 0.1.0. `Registry(detectors=None, renamed=None)` and `Registry.rename(old_id,
new_id)` in `ruleprobe/registry.py` hold the map, and `folded_rules` in `ruleprobe/report.py` applies
it on every read as a single lookup (`renamed.get(did, did)`), so a chain of renames does not resolve
to its end. The map lives only in the process that built the registry, and no shipped map or list of
shipped ids exists. A rename in 0.2.x must ship a fold entry (FR-31); without a shipped-id list
nothing catches one that does not.

## Acceptance criteria

1. **Given** `ruleprobe/contract_data.py` holding the shipped fold map and the list of every shipped
   detector id, **when** a test parses it, **then** it holds only literals. [ASSUMPTION: module name
   from AD-9]
2. **Given** a shipped map and a consumer `Registry(renamed=...)`, **when** ids are resolved, **then**
   one function uses the union, the consumer wins a clash, a chain resolves to its end, and a cycle
   raises when the registry is built.
3. **Given** rows stored under a retired id, **when** `report`, `report_data` or validity reads them,
   **then** they count under the current id through that one function.
4. **Given** `report_data` output saved as JSON, **when** it is read by a process with no registry,
   **then** it carries the effective fold map beside its rows.
5. **Given** an id on the shipped list that is neither registered in `DEFAULT` nor a fold-map key,
   **when** the suite runs, **then** it fails.
6. **Given** a `Registry` is built or `report_data` runs, **when** file access is traced, **then** no
   file is read.

## Design

### Approach

Per AD-9: a new module `ruleprobe/contract_data.py` holds the shipped fold map and the shipped-id
list as Python literals, as `SECRET_PATTERNS` is, never a data file read beside `__file__`, so it
loads the same way from a directory, a wheel or a zip. One fold function resolves ids over the union
of that map and the consumer's `renamed`, consumer winning, chains followed to the end, a cycle raised
at registry build. `folded_rules`, `report_data` and `ruleprobe/validity.py` all call it.
`report_data` emits the effective map beside its rows. Per AD-1, the new module takes its place in
the spine's dependency graph in the same change. Per AD-14, `DEFAULT` is not mutated.

### Decisions and alternatives

- Literals in a module rather than a data file: AD-9, so a zip import needs no file read (AC 6).
- AD-9 also has the same function fold a row's `compliance` map; that map arrives in Epic 2 and is
  extended there.

### Do not implement

- No rewrite of stored rows; the fold stays on read.
- No `compliance` folding (Epic 2) and no catalog module (Epic 3).

### Completion notes

- `ruleprobe/contract_data.py` holds `RENAMED` (empty: no shipped detector has been renamed)
  and `SHIPPED_IDS` (the six detectors 0.1.0 shipped in `DEFAULT`).
- The one fold function is `ruleprobe.registry.fold_map(renamed=None)`, also reached as
  `Registry.fold_map()`. It lays the consumer map over the shipped one, follows each chain to
  its end, drops identity entries, and raises `ValueError` on a cycle. `Registry.__init__` and
  `Registry.rename` call it, so a cycle raises at build or at the rename that closes it.
  A consumer's identity entry is kept only when it undoes a shipped rename; a non-string id
  raises `ValueError`, and a cycle message names each edge as shipped or consumer.
  `Registry.renamed` stays the consumer's own map, unchanged in shape.
- `folded_rules`, `errored_detectors`, `rule_ids` and `report_data` read through it;
  `folded_rules(row, renamed)` and `errored_detectors` keep their signatures and follow chains
  within the map they are handed, never merging the shipped map again; shipped renames apply
  when that map is `Registry.fold_map()`.
- `score_corpus` folds `fire` and `near` label ids through the registry's fold map without
  changing the corpus passed in.
- `report_data` emits the effective map under the key `renamed`, beside `detectors`, `groups`
  and, in `--json`, `rows`. The key name mirrors `Registry(renamed=)`; the spec does not name
  it, so it is flagged for confirmation.
- File-access tracing records the `open`, `os.listdir` and `os.scandir` audit events through
  one flag-gated `sys.addaudithook`; `Registry.from_entry_points` is excluded, since entry-point
  discovery reads distribution metadata by design and is not a build.
- Beyond AC 5, the shipped-id tests also fail a `DEFAULT` detector missing from the list and a
  shipped rename whose target is not registered.
- The spine's AD-1 graph gains `registry --> contract_data`, with a dated amendment line.

## Review findings

`bmad-build` review, three layers (blind hunter, edge-case hunter, verification gap):

- **Patched, high:** `report_data` resolved the map and its helpers folded it a second time, merging
  the shipped renames back in, so a consumer's undo of a shipped rename lost its hits and the emitted
  `renamed` disagreed with the counts. The map is now resolved once per call.
- **Patched, medium:** the file-read trace patched `io` names the import system never calls; it now
  uses an audit hook on `open`. A fire and a near label folding onto one key counted twice; that is a
  `CorpusError`. No test stopped a shipped rename from leaving its retired id in `DEFAULT`; one does.
- **Patched, low:** the idempotence claim in the docstring is corrected; `non_literal` catches every
  error `ast.literal_eval` raises; the README documents `renamed`, and `fold_map` joins
  `registry.__all__`.
- **Rejected, low:** "`Registry.renamed` is a public mutable dict": writes go through `rename`, which
  checks for a cycle; a direct write surfaces as a `ValueError` on the next read.

`bmad-code-review`, four layers (blind hunter, edge-case hunter, verification gap, acceptance
auditor; the verification gap found none):

- **Patched, medium:** `folded_rules` and `errored_detectors` kept their signatures but did one
  lookup, so an outside caller passing a raw map half-folded a chain; they now follow chains within
  the map they are handed, never merging the shipped map again. The overlap error fired on a label
  the loader allows; it now fires only when folding made the overlap.
- **Patched, low:** a consumer's undo of a shipped rename is kept in the emitted map; non-string ids
  and a cycle across the shipped and consumer maps give clear errors; validity folds through
  `registry.fold_map()`; a CLI test shows `renamed` beside `rows` in `--json`; nested traces record.
- **Deferred:** a consumer detector registered under an id a shipped rename retires counts under the
  successor and shows an empty line of its own; refusing it at `add` changes how plugins load, so it
  is the maintainer's call; logged in `deferred-work.md`.
- **Patched, low:** the changelog carries the change under `### Breaking`, added when the branch is
  rebased onto `main`.
