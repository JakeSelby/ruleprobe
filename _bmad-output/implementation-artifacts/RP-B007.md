## Reproduction

At `d775ac9`, with `from ruleprobe.shell import pipelines`:

- `pipelines("find App \\( -name '*.bak' \\) | head")` gives
  `[[['find', 'App']], [['-name', '*.bak']], [['head']]]`. A shell reads one pipeline,
  `find App ( -name *.bak )` into `head`.
- So `transcript-hygiene/unfiltered-find` hits `find App \( -name '*.bak' \)` and
  `find App AppTests \( -name '*.bak' -o -name '*.tmp' \) | head`: the first segment of a
  one-segment pipeline is `find App`, with no filter and no consumer.
- Quoted parentheses (`'('`, `")"`) and the other escaped or quoted operators (`\|`, `\&`, `\<`,
  `\>`, `\;`, `'&&'`) split the same way: `echo a \&\& find .` reads as a bare `find .`, and
  `git commit -m '(' --no-verify` hides its `--no-verify` in a second pipeline.
- `echo \(hi\)` parses correctly as `[['echo', '(hi)']]`, and `(cd a && ls)` groups correctly.

Found as a false positive of a shipped detector by the field-precision spike (#53).

## Root cause

`tokenize` in `ruleprobe/shell.py` reads the command with `shlex` in POSIX mode with
`punctuation_chars`. `shlex` removes the quoting and the backslash and returns the bare
character, so `\(`, `'('` and `(` all come back as the string `(`. `_pipelines` then decides
operator or word by string value alone (`token in _BREAK`, `token in _PIPE`), and `operands` and
`has_redirect` do the same with `_REDIRECTS`, so a quoted or escaped operator written as its own
word ends a segment or reads as a redirect. `echo \(hi\)` survives only because its word is
`(hi)`, which equals no operator. Two helpers that read raw text had the same blind spot:
`strip_comment` took an escaped `(` or `;` before `#` as a word break, and `normalise` let `\S+`
swallow a backslash so `cd a\&& ls` lost its `cd`.

## Acceptance criteria

1. **Given** `find App \( -name '*.bak' \)`, piped into `head` or not, **when** it is parsed,
   **then** the parentheses are words in the `find` segment and `unfiltered-find` does not hit.
2. **Given** a quoted `'('`/`"("` or an escaped `\|`, `\&`, `\<`, `\>`, `\;` written as its own
   word, **when** it is parsed, **then** it stays in its segment, and `has_redirect` and `operands`
   read it as an operand, not a redirect.
3. **Given** an unquoted `(`, `)`, `{ ...; }`, `|`, `&&`, `;` or `>`, **when** it is parsed,
   **then** it still opens or closes a group or subshell, splits the pipeline or redirects, as today.
4. **Given** each literal-operator shape and a reference command spelling the operator as a plain
   word, **when** every shipped detector and catalog entry runs over both, **then** their hits
   are the same.
5. **Given** a command that does not tokenize, **when** it is analysed, **then** it stays
   skipped (AD-4, #19).
6. **Given** the corpus near-miss `find . \( -name '*.bak' -o -name '*.tmp' \) | head`, **when**
   `ruleprobe corpus --no-config --floor 0.9` runs, **then** `unfiltered-find` has no false
   positive and the gate passes.

## Design

### Approach

`shlex` already reads a quoted or escaped operator as a word; what it loses is the quoting, so
`\(` and `(` come back as the same string. Before `shlex` reads the text, `_mark_literals` adds
one mark character to every quoted span and after every escaped character, following the quoting
rules `shlex` applies in POSIX mode: a single-quoted span, a double-quoted span in which only `\"`
and `\\` are escapes, and the character after an unquoted backslash. The mark joins the word
around it only because `tokenize` sets `whitespace_split`, under which every character that is
neither whitespace nor punctuation continues a word. `_unmark` strips the mark from each token
and returns it as `Literal`, a `str` subclass, when it held one. `_pipelines`, `operands` and
`has_redirect` treat a `Literal` as a word whatever its value, and `_pipelines` never drops a
`Literal` as a reserved word, so `'done' x` runs `done`. A detector comparing words sees an
ordinary string, so no detector or matcher changes. `strip_comment` no longer starts a comment
after an escaped character, and `normalise` reads an escaped character as part of the `cd`
directory.

### Decisions and alternatives

- 2026-09-24: `\;` stays in its segment as a word. It used to end the segment, which no detector
  depended on; `find . -exec cat {} \;` now reads as the one command a shell runs.
- 2026-09-24: text that already holds a mask character is tokenized unmasked, exactly as before,
  so a transcript cannot forge a literal.
- 2026-09-24, code review: supersedes the entry above. The mark is chosen per command: the first
  code point in the supplementary private-use area, U+F0000 to U+FFFFD, that the command does
  not hold. A transcript still cannot forge a `Literal`, and a command holding a Nerd Font glyph
  from U+E000 is still marked. Only a command holding all 65,534 of them is read unmarked. One
  mark, not one per operator character, since `shlex` never splits a quoted or escaped
  character and the mark only has to say that a word was quoted.
- 2026-09-24, code review: every quoted or escaped word is a `Literal`, not only one holding an
  operator character, and `_DROP` skips a `Literal`. `'done' x`, `\!`, `'{'` and `"}"` name
  the command, as in bash.
- Rejected: subclassing `shlex` to record which tokens came from punctuation state. It reaches
  into `read_token`'s private states, which differ across the 3.9 floor and later versions.
- Rejected: rewriting `\(` to a placeholder word in the raw text. It would change the word a
  detector sees and miss the quoted and in-word forms.
- Rejected: a second tokenizer in the detector. AD-5 keeps the shared parse the only Bash
  decomposition.

### Must not change

The parse of every unquoted operator, the strings a segment holds, the skipped status of a
command that does not tokenize, and every detector's hits on a command without a quoted or
escaped operator.

## Review findings

Code review, four layers (blind hunter, edge-case hunter, verification gap, acceptance auditor):

- **Patched, should-fix:** any character from U+E000 to U+E006, such as a Nerd Font glyph,
  turned masking off for the whole command. The mark is now the first supplementary private-use
  code point the command does not hold (Decisions), tested with a U+E000 command and with one
  holding U+F0000.
- **Patched, should-fix:** a quoted or escaped reserved word was dropped, so the next word read
  as the command. Every quoted or escaped word is now a `Literal` and `_DROP` skips it; tested
  with `'done' x`, `\!`, `'{'` and `"}"`.
- **Patched, should-fix:** the double-quote escape branch had no test. `"\"" "("`,
  `"\\" "|"` and `echo "say \"hi\"" && find .` now pin it, the last also in the detector sweep.
- **Patched, note:** the comment claimed a private-use character is a `shlex` word character. It
  now names the dependency on `whitespace_split`.
- **Patched, note:** `operands` and `has_redirect` were tested only with `\>`. Quoted `'('` and
  `"("`, `\<` and `\|` are added; the sweep gains a quoted `'&&'` and a lone `\&`.
- **Patched, note:** AC 5 was tested only with an unterminated quote. Three commands that do not
  tokenize and hold an escaped operator stay skipped, with `tokenize(strict=True)` giving None.
- **Patched, note:** `strip_comment` gains an escaped `;` before `#`, `echo a\ #b` (no comment)
  and `cat a\\ #x b.txt` (a comment), each checked against bash. The edge-case hunter's
  low-confidence claim that the second changed was wrong: the guard only covers the character a
  backslash escapes, so the space after `\\` still starts a comment, as before.
- **Not changed:** `CHANGELOG.md`. Its `## Unreleased` line comes from the orchestrator in the
  same pull request, so it is not in this file list.
- **Not changed:** the `issue-map.json` reorder and `generated_at`. The map edit was already in
  the worktree when this work began, and it is out of this fix's scope; it is raised to the
  orchestrator.
- **Not changed:** `Parsed.normalised` has no detector consumer; the `normalise` change is covered
  by its direct test.
