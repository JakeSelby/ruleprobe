## Story

As a maintainer of a rule set,
I want `order` and `absent` detectors to report opportunities and whether each was followed,
so that a rule's compliance can be counted without a new detector.

## Context and value

Hits per session answer "how often did this happen", not "how often was the rule followed when it applied". Maintainer decision 3 makes compliance per opportunity the one user-facing advance of 0.2. This story gives `Detector` the keyword-only `opportunities` attribute AD-11 defines and has the `order` and `absent` (`scope: turn`) compilers produce it from the same evaluation that yields their hits. RP-S012 and RP-S013 build on it. Today `Detector` is `Detector(id, rule, event, fn, gate=None, examples=None)` with `__slots__`, and `_a_absent` with `scope: turn` returns one hit per turn in which `of` never matched.

## Acceptance criteria

1. **Given** `Detector`, **when** built positionally with five arguments, **then** it behaves as in 0.1.0; **and** `opportunities` can be set by keyword only.
2. **Given** an `absent` detector with `scope: turn`, **when** compiled, **then** each turn in the event list is one opportunity, followed when `of` matched in that turn.
3. **Given** an `order` detector, **when** compiled, **then** each `first` match opens one opportunity, followed when `then` matched within `within`.
4. **Given** an `absent` detector with `scope: session`, **when** compiled, **then** it defines no opportunity.
5. **Given** an opportunity whose `followed` is undecided (AD-4), or whose `first` is undecided, **when** counted, **then** it is `undecided`, never not-followed. [ASSUMPTION: from AD-11, `first` undecided counts as undecided]
6. **Given** every compiled detector over the corpus, **when** tested, **then** hits = opportunities - followed for `absent` and hits = followed for `order`, as AD-11 writes it. `opportunities` excludes undecided, so undecided is not subtracted again.
7. **Given** the contract test, **when** this lands, **then** it covers the keyword `opportunities` attribute in the same change.

## Design

### Approach

Add `opportunities` to `Detector.__slots__` and as a keyword-only parameter defaulting to `None`, keeping the 3.9 floor (a `*` marker in the signature). The attribute is a callable over `(events, ctx)` returning `(turn, tool_use_id, followed)` triples, `followed` in `True`, `False`, `None` (AD-11). In `matchers.py`, `order` and `absent` with `scope: turn` compute triples in the same pass that yields hits, so the identity in AC6 holds by construction; the code in `matchers.py` that builds each `Detector` attaches the callable. Polarity comes from the matchers: `absent`'s `of` is the asked-for action; a hit for `absent` is an opportunity not followed, and a hit for `order` is a followed opportunity.

### Decisions and alternatives

- The hook's form is RP-D005 (PRD Q10). This story builds AD-11's form; if RP-D005 replaces it, this design follows the decision.
- Widening `fn`'s return was rejected by AD-11: it would change the shape every downstream detector relies on.
- A trigger key for `absent` is deferred by the spine as an AD-7 vocabulary change; without it, every turn is an opportunity.

### Do not implement

- No `compliance` in rows or the report (RP-S012, RP-S013).
- No opportunities for `change`, event matchers or `absent` with `scope: session`.
- No new matcher key, no change to `fn`, `run()` or their returns.
