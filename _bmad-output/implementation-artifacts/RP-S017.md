## Story

As a developer surprised by a hit,
I want to see the event and detector behind it,
so that I can judge whether the hit is right.

## Context and value

`report` prints counts per detector (FR-17) and nothing that ties a count to an event, so a surprising
number cannot be checked. FR-25 asks for an explain path per hit, redacted, writing nothing, and SM-7
targets 100% of hits in a run over transcripts. It also produces the address `ruleprobe label`
(RP-S018) takes, so it unblocks the rest of Epic 4. Today there is no `explain` subcommand and no
`redact` function; `SECRET_PATTERNS` is a list in `ruleprobe/detectors/common.py` used only to
detect secrets.

## Acceptance criteria

1. **Given** a report run over transcripts, **when** `ruleprobe explain` runs, **then** every hit
   prints the session, turn, tool-use id, detector id and the matched field, keyed with `hit_key`.
2. **Given** an event holding a known secret shape, **when** explained, **then** the shape never
   appears in the output; a single `redact` beside `SECRET_PATTERNS` is the only path, and
   `SECRET_PATTERNS` stays a plain literal assignment.
3. **Given** a stored row, **when** explained, **then** the output says the row carries counts only
   and names the rerun over that row's runtime and session id. [ASSUMPTION: a library function takes
   the row; the CLI has no stored-row input]
4. **Given** explain runs, **when** the file system and report figures are checked, **then** nothing
   is written and no report number changes.
5. **Given** the CLI form `ruleprobe explain [--session ID] [--detector ID] [--key KEY]` plus
   `report`'s source options (`--root`, `--runtime`, `--since`) and the shared detector options
   (`--rules`, `--detectors`, `--no-config`), **when** run with no filter, **then** it prints every
   hit; each filter narrows the output, and a filter that matches nothing prints nothing and exits 0.
   [ASSUMPTION: this CLI form; AD-13 fixes only the subcommand names]
6. **Given** a hit, **when** printed, **then** its address is the session (`<runtime>:<Session.id>`)
   plus the `hit_key`, because a key `"<turn>:<tool_use_id>"` is unique only within a session; the
   printed address is exactly what `ruleprobe label` takes. [ASSUMPTION: `Session.id` is unique within
   a runtime, so the runtime prefix makes it unique across runtimes]

## Design

### Approach

Explain reruns detectors over transcripts and prints from `Hit` keys (AD-13). It builds keys only with
`hit_key` from `ruleprobe/validity.py` (AD-6). Every printed string passes through one `redact`
function added beside `SECRET_PATTERNS` in `ruleprobe/detectors/common.py`. It shares `report`'s
source options and `_declarative_options`, so the hits it lists are the hits `report` counts.

### Decisions and alternatives

- Rows are not widened to carry hit keys; a stored row gets a counts-only message and the rerun that
  would explain it (AD-13).
- The CLI form and the stored-row library entry point are assumptions carried from `epics.md`.
- 2026-09-23: `explain` also takes `--stance` and `--plugins`, as `report` does. Without them,
  gated and plugin detectors never run, and explain could not list every hit `report` counts.
- 2026-09-23: explain's stderr carries the unread-transcripts line, the detector-error line
  (three named, then "and N more") and the bundle summary, so a skipped detector is not
  silent. Each line is redacted.
- 2026-09-23: every printed string is redacted. Control characters and bidi or line-separator
  marks (U+200E, U+200F, U+2028, U+2029, U+202A-U+202E, U+2066-U+2069) print as `\xNN` or
  `\uNNNN` escapes, so a transcript cannot drive the terminal or reorder a line.
- 2026-09-23: one event's printed text is capped at 4,000 characters, with a note of how many
  were cut.
- 2026-09-23: after a secret key name, redaction takes the rest of the line and parses
  nothing. It takes the next line too when the rest holds no value, and each line after a
  backslash continuation. Redaction-only key-name patterns sit in their own literal,
  `SECRET_KEY_PATTERNS`, beside `SECRET_PATTERNS`, so a quoted or subscripted key is caught.
  A shape that is itself the secret takes the rest of its token, and a private key runs to its
  footer.
- 2026-09-23 (second review): `redact` merges spans. Every pattern is matched against the
  original text, each match is widened, and overlapping or touching spans are merged and
  replaced once, so no pass reads another's output. A token ends at whitespace, a quote, a
  backslash, a comma or a bracket. A private key runs to its footer across `\n` escapes. A
  key name runs through its line (a real newline or a `\n` escape ends one), its
  continuations and, when the rest of its line holds no value, the indented or blank lines
  below and at least the next non-blank one. A quote its line leaves open (`"`, `'`, a
  backtick or a JSON-escaped `\"`) carries it to the closing quote, across real newlines and
  `\n` escapes, or to the end of the text. Redaction-only literals add token shapes (`sk-ant-`, `sk-proj-`,
  `github_pat_`, `gh[opsur]_`, `xox[abprs]-`), a URL's password, and generic key names before
  a `:` or `=`. Every Unicode format character (Cf) is escaped. A non-string field is
  stringified and redacted. The `--session`, `--detector` and `--key` filters compare values
  before redaction, inside `explain()`.
- 2026-09-23: `explain_row` gives the bare session id in the rerun whenever the row's runtime
  is missing or is not among the known runtimes passed in. No reader emits the
  `<runtime>:<id>` address for such a runtime.

### Do not implement

- No write of any kind; labelling is RP-S018.
- No change to row shape or report figures.
- No fix or suggestion for a wrong hit; no model call.

### Completion notes

- `redact` sits beside `SECRET_PATTERNS`, which stays a plain literal. Its rules are the
  2026-09-23 decisions under Design. The redaction-only `SECRET_KEY_PATTERNS`,
  `SECRET_NAME_PATTERNS` and `SECRET_TOKEN_PATTERNS` are plain literals beside it.
- `report.explain(sessions, stances=None, registry=DEFAULT, errors=None)` reruns `run()` and
  yields one dict per hit. `report.explain_text(item)` renders the printed block, and
  `report.explain_row(row)` covers AC 3. The address is `report.session_address()`. Keys come
  from `validity.hit_key`. Every printed value and line passes through `report._redact`, which
  is `redact` plus an escape for each control, bidi or line-separator mark. Every string field
  of a yielded item and of an error entry is redacted, and a value is cut at 4,000
  characters with a count of what was cut. The printed event is found by `(turn, id)`, and
  `run()` gets the session's events unchanged, as `measure()` passes them.
- A `Hit` does not record which field matched. The "matched field" is the Bash `command`, or
  any other tool's whole input as sorted JSON, falling back to `repr` when JSON cannot hold it.
  A hit that names no tool use has no event, and the block says so with its turn.
- `report.py` reaches `validity.hit_key` and `detectors.common.redact` through imports inside
  functions, which the AD-1 amendment sanctions. `report` imports no reader:
  `explain_row(row, runtimes=())` takes the known runtime names as an argument, and names
  `--runtime` only for one of them.
- `explain` takes the CLI form in AC 5 plus `--stance` and `--plugins`, as `report` has them,
  so gated and plugin detectors run. The bundle summary, findings included, goes to stderr.
  `--detector` folds a renamed id through the registry.
- `--session` accepts the printed address or the bare session id. Sessions are streamed.
  Detector errors, read errors and the bundle summary go to stderr, redacted. Exit 1 only
  when no transcript was read at all, as with `report`.
- `explain_row` names `--runtime` and the `<runtime>:<id>` address only for a runtime in its
  `runtimes` argument, the bare id otherwise, and shell-quotes each value. A
  row with no `rules` map is reported as carrying no counts.
- The new names are not added to the declared public API; the README describes
  the stored-row helper as undeclared, with no call shape.
- Most tests are in the new `tests/test_explain.py` rather than in the shared test files, to
  stay clear of parallel work in them. `tests/test_envelope.py` gains an explain class.
