# RP-D011 — decision(draft): whether the drafting command belongs in 0.2.0, a later minor or nowhere

This work item was authored as part of the repository's committed BMad planning system.

## Context

Maintainer decision 2 (2026-09-23) allows a model-assisted path that drafts a detector from a rule's
prose only as a separate opt-in command that emits data a person commits, and calls it a proposal,
not a commitment. PRD Q4 asks whether it belongs in 0.2.0, a later minor or nowhere, and is needed
before v0.2.0 scope is frozen. AD-8 already fixes the boundary: outside the core install, the core
never imports it, no model in `report`. FR-34 leaves open whether it is an optional extra or a
separate package.

The question: where the drafting command lands, and, if built, how it is packaged.

## Options

1. **0.2.0.** For: it attacks the cost of writing a detector from nothing. Against: it widens a
   release whose scope is the versioned contract, and it adds a model-bearing surface beside a
   product whose value is no model in the measurement loop.
2. **A later minor.** For: 0.2.0 ships without it and the boundary in AD-8 is already fixed.
   Against: it stays an open item.
3. **Nowhere.** For: the narrowest product, and no model anywhere in the repository. Against: users
   keep writing every detector by hand, with only the catalog (FR-16) to start from.

If built: an **optional extra** keeps one distribution, but the core's `pyproject.toml` then names
it; a **separate package** keeps the core metadata untouched and costs a second release to manage.

## Decision

Decided 2026-09-23 by the maintainer: drafting a detector from prose belongs nowhere in ruleprobe.
It moves into the scope of the future judge library tracked in #21 (RP-E002), because it needs a
model. FR-34 is withdrawn from ruleprobe, and NFR-7's exception for FR-34 is removed, so no command
in ruleprobe calls a model. This is the narrowest product, with no model anywhere in the repository.

## Consequences

- RP-E009 and RP-S020 are withdrawn unbuilt; their content is kept, and drafting joins RP-E002's
  scope.
- NFR-7 drops its FR-34 exception, and AD-8 drops the drafting-command boundary.
- Users write every detector by hand, with the catalog (FR-16) to start from.
- The optional-extra or separate-package question no longer applies to ruleprobe; NFR-1's test still
  sees `dependencies = []`.
