## Story

As a developer with dense rule files,
I want each sentence to bind its own detector,
so that a section mixing several rules is measured rather than dropped.

## Context and value

The 0.2.0 binder reads a section as one unit: two matching sentences, or one exception word
anywhere, leave the whole section unmeasured. On the rules zoo it measures recall 0.44 (18/41) with
no false bind (story 8.2, #139). RP-SP004 (#137) measured a per-sentence prototype at 0.73 recall
with five false binds, every one an exception stated in the sentence after the rule, and variant B,
which lets that next sentence unbind, at 0.68 with one false bind, the "exempt" gap 8.2 closed. Its
decision, taken under the maintainer's delegation, is that this story builds variant B, and that the
0.70 recall bar moves to Epic 8 as a whole, since 9 of the 11 misses are catalog phrasings (8.4).
After two reviews of PR #142 found false binds variant B's narrower exception reach let through, a
second decision under the maintainer's delegation, flagged to him, moved the build to variant S:
per-sentence binding with 0.2.0's section-wide exception scope.

## Acceptance criteria

1. **Given** a section whose two sentences each match a different catalog entry, **when** it binds,
   **then** it binds both, and the rule id is still AD-12's section id.
2. **Given** a sentence matching no entry or several, **when** it binds, **then** that sentence binds
   nothing.
3. **Given** "if" in one sentence, **when** the section binds, **then** only that sentence is
   unbound. (Amended for variant S: the epic's "unless" now unbinds the whole section, as 4 says.)
4. **Given** an exception or permission anywhere in a section, its heading included, **when** the
   section binds, **then** every rule in it is unbound; **given** a condition or contrast word,
   **then** it unbinds only the sentence it is in.
5. **Given** "admit no exception" or "without exception", **when** the sentence binds, **then** the
   marker does not unbind it.
6. **Given** the zoo, **when** `corpus` runs, **then** it shows zero false binds, and the recorded
   recall floor is the recall measured.
7. **Given** a section several detectors measure, **when** `report` prints the coverage block,
   **then** its line lists them all.

## Design

### Approach

- `rules._match` returns one `_Sentence` (paragraph, offset, text, detectors, marker) per
  sentence, heading first, over the `_sentences` split. A matching sentence's marker is an
  exception or permission word (`_EXCEPTION`) anywhere in the section, heading included, else a
  condition or contrast word (`_CONDITION`) in the sentence itself (variant S). Both word lists
  read the text after the catalog's negated markers, at the end of a clause, are removed.
- `rules._binding` returns the entry and the sentences that bound it (`_binds`); `_bind` is its
  entry, and `validity.score_binding` scores the pairs line by line, so the gate scores the
  binder's own output.
- `rules._bound` keeps each sentence that matched exactly one live entry and has no marker, and
  returns those entries in catalog order, once each. `_bind` makes the rule measured and
  catalog-bound to all of them; with none, it names the first unbinding word, else the first
  sentence's several matches (the reasons 0.2.0 printed), else the caller's reason.
- `catalog.NEGATED_EXCEPTIONS` is the closed list, as plain phrases in the literals-only catalog
  module; `rules._NEGATED` compiles it longest first, whitespace-tolerant, singular or plural.
- A heading-less file, or a headed file with no rule section, binds per sentence the same way.
- `validity.BINDING_RECALL_FLOOR` rises from 0.43 to 0.65 under variant S (0.68 under variant B).
- No output shape changes: `RuleEntry.detectors` was already a list, the coverage line already
  joins it, and `report --json` carries counts only. Nothing goes under Breaking.

### Decisions and alternatives

1. **Variant S's scope** (decision of 2026-09-25 at PR #142's second review, under the
   maintainer's delegation and flagged to him): an exception or permission anywhere in a section
   unbinds every rule in it; the per-sentence multi-bind stays. Superseded: variant B's
   next-sentence scope (RP-SP004's decision), built first and widened once at review to the
   sentence before and colon lead-ins; each widening left another markdown shape - a list item of
   two paragraphs, a lead-in ending in a period, an unlisted abbreviation - carrying an exception
   past it. Rejected: own-sentence scope, five false binds; the refer-back refinement, retired with
   variant B.
2. **A heading's exception or permission unbinds the whole section.** Settled by the maintainer
   earlier, and now one case of decision 1.
3. **Detectors in catalog order, deduplicated,** not sentence order, so reordering a section's
   sentences never changes its report line.
4. **A mixed-source rule stays one entry.** A user detector replacing one bound id makes the whole
   rule `own`, and a bound id the registry no longer holds leaves the whole rule unmeasured, as
   `_sourced` already does; both under-count. Rejected: splitting a section into one entry per
   detector, which would change AD-12's rule id.
5. **The negated markers live in the catalog module** as AD-18 says, as phrases rather than a
   regular expression, so the module stays literals only and the list stays readable.

### Do not implement

- Wider catalog patterns or patterns for the four uncatalogued defaults (story 8.4).
- Any exception scope narrower than the section (variant B, lead-ins, refer-back).
- Any zoo label change, or a looser false-bind gate.

## Review findings

Review of PR #142 at `4558d9a`, all resolved in one `fix(rules)` commit:

1. **Blocker: an exception in the sentence before a rule never unbound it**, so a lead-in bound
   where 0.2.0 left the rule unmeasured ("Except on release branches:" over "- Never force-push to
   main."). Resolved: an exception or permission now reaches the sentences either side, and a
   paragraph or list item ending with `:` that grants one carries it over the list items straight
   after it, or the next paragraph when no list follows (`rules._introduced`). Both inputs joined
   the zoo as near-misses `f11` and `t13` (kind `lead-in-exception`); the zoo is now 67 sections
   and 88 labels, and `SHIPPED_ZOO_SHA256` is re-keyed to its new bytes. Tests: the sentence
   before, five lead-ins that unbind, and two that do not.
2. **Abbreviations and asides split sentences** and pushed an exception out of reach. Resolved:
   `rules._split` never ends a sentence inside parentheses (an unmatched `(` keeps the rest whole)
   or after e.g., i.e., etc., vs. or cf.; the docstring now says an unlisted abbreviation still
   splits, rather than claiming a split only under-counts. Tests for each abbreviation, nesting,
   an unmatched bracket either way, and two rules that the split had left bound.
3. **A negated marker matched the start of a compound noun** ("without exception approval",
   "with no exception ticket open"). Resolved: a marker is negated only where its clause ends after
   it (`rules._CLAUSE_END`); the catalog list is unchanged. Tests for both inputs and four
   clause endings.
4. **The gate scored detector ids per section**, so one sentence's false bind was masked by
   another line's label. Resolved: `validity.score_binding` scores per labelled line, the heading
   one of them, and `_match` gives each sentence its paragraph and offset, which `_attributed`
   places on the line it starts on. A test counts an unlabelled binding line as fp=1 beside a
   labelled one; another places a wrapped sentence and a heading bind.
5. **Note: a literal typographic apostrophe** was the only non-ASCII in `rules.py`. Resolved: the
   `\u2019` escape is back, the dash class is escaped too, and a test holds the file to ASCII.

Zoo figures after the first round: recall 0.68 (28/41), precision 1.00, no false bind, scored per
line; the floor stayed 0.68 under the new zoo hash. The two new items are the review's own inputs,
null-labelled near-misses that add no positive.

Second review of PR #142 at `709cdf6`, resolved in one `fix(rules)` commit by moving to variant S:

6. **A list item of two paragraphs broke the lead-in's reach** ("Except on release branches:" over
   "- Keep commits small." and its continuation "Squash first.", then "- Never force-push to
   main."). Resolved by variant S: the exception unbinds the whole section. Zoo `f12`; tests.
7. **A lead-in ending in a period was no lead-in** ("These apply except on release branches.").
   Resolved by variant S. Zoo `f13`; tests.
8. **An unlisted abbreviation split the rule from its exception** ("Never force-push to main,
   incl. tags, e.g. v1.2. Release tags are fine."). Resolved by variant S, under which a split
   never moves an exception out of reach; the README's aside claim now rests on that, and names the
   one over-count a split still allows, a condition word. Zoo `f14`; tests. A lead-in over three
   list items is zoo `f15`.
9. **`validity._attributed` re-implemented `_bound`'s test.** Resolved: `rules._binding` returns the
   entry and the sentences that bound it, `_bind` is its entry, and the gate places those binds on
   lines, counting only detectors the entry lists and failing on one it cannot place. A test
   changes the binder's decision under the gate and sees the tally move.

The zoo is now 71 sections and 103 labels; blank lines inside `f12` and `f13` are null-labelled
lines, so they count as labels. `SHIPPED_ZOO_SHA256` is re-keyed. Checked against the `709cdf6`
binder, the new zoo fails with three false binds (`f12`, `f13`, `f14`).
