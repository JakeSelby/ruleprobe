## Story

As a first-time user,
I want `ruleprobe report` to find my rule files itself,
so that my first run needs no flags.

## Context and value

Before this story, `report` with no `--rules` read no rule file, so a stranger's first run printed
the detector table and nothing about their own rules. Stories 8.3 (#141, per-sentence binding,
variant S) and 8.4 make catalog binding worth running on an unedited rule file; this story points it
at the files the agent actually loaded. It is the last piece of Epic 8's "a first run with no
configuration" (#128) and FR-38.

## Acceptance criteria

1. **Given** no `--rules`, **when** `report` runs, **then** it reads `~/.claude/CLAUDE.md`,
   `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md` and the project rule files at each session's recorded
   working directory.
2. **Given** an unmeasured section, **when** the coverage block prints, **then** it names the nearest
   catalog entry and the word that blocked the bind.
3. **Given** any discovered run, **when** the coverage block prints, **then** it says the rule text is
   today's, not the text in force when an older session ran.
4. **Given** a fixture home with one bindable rule, **when** `report` runs with no flags, **then** that
   rule is measured inside 60 seconds.
5. **Given** a discovered run, **when** it finishes, **then** no file was written.

## Design

### Approach

- Each reader keeps the working directory it already parsed on a new trailing `Session.cwd` field
  (default `""`): Claude Code's `cwd`, Codex's `session_meta` `cwd`, Gemini's `.project_root`. No
  report row carries it.
- `cli.cmd_report`, when neither `--rules` nor `--no-config` is given, makes a first pass over the
  same `iter_sessions` call, keeping only `(runtime, cwd)` pairs, then calls
  `rules.find_rule_files`, and hands the list to `load_bundle(rule_files=...)` before the measuring
  pass builds its registry.
- `rules.find_rule_files(workdirs, home)` returns a sorted, deduplicated list of real paths: the
  global file of each runtime under `home`, then at each existing working directory that runtime's
  project files (`PROJECT_RULE_FILES`, `PROJECT_RULE_DIRS`), then `@path` imports from Claude Code
  and Gemini files, breadth first, `IMPORT_DEPTH` = 5 hops, then `_distinct` drops a file whose
  bytes an earlier one holds.
- `load_bundle` reads each found file through `read_rule_file(path, label=_label(path))`, so rule
  ids read `~/work/app/CLAUDE.md#testing`; the path column is left out where the id already says it.
- `Bundle.found` holds the found list; `summary()` opens with one line, "rules found with no --rules
  in N files; the rule text is today's, not the text in force when an older session ran", whenever it
  prints anything.
- `_binding`'s blocked-bind reason keeps its text and adds the entries the blocked sentence matched:
  `a catalog shape with an exception or condition (unless), nearest git-safety/force-push-default`.
- `_short` prints a path outside the working directory as `~/...` when it is under the home
  directory, which its docstring already promised.

### Decisions and alternatives

1. **Discovery runs only with no `--rules` and no `--no-config`.** `--no-config` already means "read
   none of the user's configuration"; rule files are that too, and it gives tests and scripts a way
   out. Rejected: also skipping discovery under `--root`, which AC1 does not allow.
2. **Project files per session runtime.** A Claude Code session's directory reads Claude Code's
   files, a Codex session's reads `AGENTS.md`: the runtime is what loaded them. The three global files
   are read whenever they exist, as AC1 names them. Codex's documented `AGENTS.override.md` is read in
   place of `AGENTS.md` where both exist.
3. **Two passes, not a held session list.** The first pass keeps no events, so memory stays one
   session deep. It costs a second parse, about 0.6 s on the 500-transcript reference volume (the
   figures are under Completion notes), far inside NFR-9's 60 s. Rejected:
   materialising every session (memory grows with the volume), and a cheaper per-reader cwd probe
   (more reader surface, and it would bypass the `--since` and copy handling).
4. **Imports followed, bounded.** Claude Code's global files commonly import the rest with
   `@~/...`; not following them would miss most of a real rule set. Only an existing `.md` target on
   a text line, outside code spans and fences, `~/`, relative or absolute, five hops (Claude Code's
   documented limit), cycles cut by a seen set. Codex files do not import.
5. **Same bytes, one file.** Several worktrees of one repository otherwise list the same rules once
   per worktree, inflating the unmeasured count; the shortest path names the file, so a checkout wins
   over a worktree nested in it, and sorted order breaks a tie.
6. **Nearest entry only where a pattern matched.** A section no pattern matched has no nearest entry
   and none is guessed: a similarity guess would be a new, unscored binder.
7. **Rule ids by location.** A label `~/<path>` (or the whole path outside home) replaces the
   `--rules`-relative path, so two projects' `AGENTS.md` never share an id. A front-matter detector
   keeps its slash-free file-stem `rule`.
8. **Nothing printed when nothing is found.** A run with no rule file anywhere prints what it
   printed before.

### Do not implement

- Walking parent directories of a working directory, `~/.claude/rules`, `CLAUDE_CONFIG_DIR`,
  `CODEX_HOME` or Gemini's `context.fileName`: recorded as known misses in `find_rule_files`.
- Discovery in `detectors`, `explain`, `label` or `corpus`.
- A `--json` field listing the found files.

## Review findings

The workflow's three independent review layers (blind hunter, edge-case hunter, verification gap)
were not run: the builder ran as a subagent that may not launch reviewers. They are pending for the
maintainer before the PR. A self-review of the diff found and fixed:

1. `find_rule_files` sorted the raw working directories before checking their type, so a
   transcript's non-string `cwd` beside a string one raised `TypeError`. Fixed: filtered first;
   covered by `test_a_working_directory_that_is_gone_or_blank_reads_nothing`.
2. Byte dedup kept the first path in sorted order, so `.claude/worktrees/x/AGENTS.md` named a rule
   ahead of the checkout's own `AGENTS.md`. Fixed: shortest path first.
3. `_short` began printing a path outside both the working directory and home with `/`
   separators. Fixed: such a path prints exactly as before.

4. Test isolation: `tests/test_findings.py` ran `report` with neither `--rules` nor `--no-config`,
   so it read the real home's global rule files. Fixed: its CLI helper runs every command under an
   empty temporary `HOME`. Checked by running the whole suite with `HOME` at a sentinel home holding
   the three global files and an `open` probe on `sys.path`: no test opened one, while a control
   `report` run under the same probe did.
