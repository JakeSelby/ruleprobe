## Reproduction

At `904f737`, `secrets/secret-in-write` fires on any Write or Edit text, or Bash heredoc body,
that one of `SECRET_PATTERNS` matches anywhere. Each of these synthetic writes is a hit, and none
writes a credential:

- a doc that names the variable: ``Export `AWS_SECRET_ACCESS_KEY` first.`` (the bare key name
  matches `(?i)aws_secret_access_key`);
- code that reads it: `client_secret = os.environ["CLIENT_SECRET"]` (`client_secret\s*[:=]`);
- an example env file: `SLACK_BOT_TOKEN=xoxb-your-token-here`, `OPENAI_API_KEY=sk-xxxx...`
  (the `xox[bp]-` prefix alone, and an `sk-` run of one character);
- a scanner's source: `re.compile(r"(?i)aws_secret_access_key\s*[:=]...")`;
- redaction code: `for prefix in ("AKIA", "ghp_", "xoxb-", ...)`.

The field spike (#53's Result) judged 23 hits from real transcripts: 1 right, 20 wrong, 2 unsure,
precision 0.05. The wrong hits were writes about secrets - environment-variable names, pattern
sources, placeholders and redaction code - the classes above. The shipped corpus scored the
detector 1.00 throughout, because it held no near-miss of these kinds.

## Root cause

`_secret_in` in `ruleprobe/detectors/common.py` searched `SECRET_PATTERNS`, the list `redact`
prints through. Those patterns are broad by design: redaction must remove a key name with its
line, a bare prefix, anything secret-shaped, and over-redacting is its safe side. Detection
reused them unchanged, so it counted a mention - a key's name with no value, a prefix with no
token, a placeholder, a pattern - as a write of the secret. Three of the eight patterns
(`aws_secret_access_key`, `client_secret\s*[:=]`, `xox[bp]-`) need no value at all, and the
others accept a placeholder or a run of one character. The declarative twin in
`ruleprobe/detectors/common.yaml` and the restating catalog entry carry the same list.

## Acceptance criteria

1. **Given** a Write, Edit or heredoc that writes an issuer-shaped credential with a value - an
   AWS access key id, `aws_secret_access_key` or `client_secret` assigned a literal, a Bearer,
   GitHub, Slack, OpenAI or Anthropic token, or a private-key header followed by a body -
   **when** the detector runs, **then** it is a hit.
2. **Given** a write that names a secret's variable or reads its value from the environment,
   **when** the detector runs, **then** it is no hit.
3. **Given** a write whose only credential-shaped text is a placeholder (`xxx`, `<your-key>`,
   `changeme`, `${VAR}`, `sk-...`, a token of one repeated character), **when** the detector
   runs, **then** it is no hit.
4. **Given** a write whose credential-shaped text sits on a line that reads as a pattern source
   (`re.compile(`, a character class, a quantifier, a regex escape) or as redaction code
   (`redact`, `mask`, `scrub`), **when** the detector runs, **then** it is no hit.
5. **Given** a Write or Edit to a test path whose token's own line marks it fake, **when** the
   detector runs, **then** it is no hit; the same value in a non-test path, in a test path with
   no such mark, or with the mark on another line, is still a hit. (Amended 2026-10-03 by the
   review, finding 3: the mark was file-wide.)
6. **Given** any text, **when** `redact` runs, **then** it removes everything it removed before:
   `SECRET_PATTERNS` and `redact` are unchanged, and every hit's value is one `redact` removes.
7. **Given** the shipped corpus, **when** `ruleprobe corpus --floor 0.9` runs, **then** the
   detector carries a labelled near-miss for each class in AC 2 to 5 beside its positives, every
   one of which the old detector fired on, and it clears the floor.
8. **Given** a hostile text of 200,000 characters, **when** the detector scans it, **then** it
   finishes in under a second.

## Design

### Approach

Keep `SECRET_PATTERNS` and `redact` as they are and add a detection-side filter:
`_LIVE_SECRET_PATTERNS`, eleven regexes in `ruleprobe/detectors/common.py`, each narrower than a
shape `redact` already removes. A credential counts only as an issuer's shape with a value
behind it. Each value carries lookaheads: no placeholder word in it, no `UPPER_SNAKE` or
`lower_snake` variable name, and for a token both a letter and a digit, which also rules out a
token of one repeated character. The private-key body and a quoted `client_secret` literal
instead refuse a run of one repeated character. Each token is wrapped so it must sit on a line
that holds no pattern-source or redaction-code marker. In a Write or Edit to a test path, a
token whose own line marks it fake (`fake`, `dummy`, `not a real`, as whole words) is skipped;
that is a second pattern list, `_LIVE_SECRET_PATTERNS_IN_TESTS`, chosen by the path. The same strings are written
out in `common.yaml` and the catalog entry, since the catalog holds literals only and the YAML
subset cannot compose; a test pins both to the Python list.

### Decisions and alternatives

- 2026-10-03: detection gets its own patterns; `SECRET_PATTERNS` keeps its name, shape and
  contents. It is public, and `redact` and `label`'s refusal read it, so narrowing it would weaken
  redaction. The brief allowed this split: keep redaction broad, filter on the detection side.
- 2026-10-03: the only entropy check is letters-and-digits for a token value. It is exact, needs
  no threshold and keeps the corpus's obviously synthetic `EXAMPLE` values counting; a Shannon
  threshold would have to be tuned on real tokens nobody may ship. No checksum is checked: only
  GitHub's tokens carry one, and the corpus may not hold a valid one.
- 2026-10-03: `EXAMPLE` is not a placeholder word. The corpus contract keeps positives visibly
  synthetic, and AWS's own documented example ends in `EXAMPLE`; the detector cannot tell one
  from a live key, and the README says so.
- 2026-10-03: the context checks are line-scoped regex lookaheads rather than Python code, so the
  declarative twin can say exactly the same thing and the equivalence test holds. A token's left
  edge excludes its own body's characters, so a match never starts inside another and the scan
  stays linear.
- 2026-10-03: Anthropic (`sk-ant-`), OpenAI project (`sk-proj-`), `github_pat_` and the other
  `gh?_` tokens now count; `redact` already removed each, so the hit-is-redacted rule holds.
  `SECRET_PATTERNS`' own `sk-` pattern never matched them.
- 2026-10-03: two synthetic test values became live-shaped: `tests/corpus.py`'s `FAKE_KEY` was a
  run of one repeated character, and the gemini-git heredoc positive (`1:tu-b54`) wrote the one
  word `EXAMPLE` after `aws_secret_access_key`. Both are now the placeholders AC 3 excludes;
  giving them a mixed value keeps each test on its subject.
- Rejected: a Python-only filter (path, entropy, context) after `SECRET_PATTERNS` matched. The
  declarative twin could not express it, and the twin is a shipped promise.
- Rejected: dropping a hit whenever the whole text holds `re.compile` or `redact`. A line scope
  under-counts less and still clears every field class.

### Must not change

`SECRET_PATTERNS` (name, shape, contents), `redact`, `label`'s refusal, the detector id and its
`write` event, and what a Bash command outside a heredoc counts (nothing, unless it is too long
to parse).

## Review findings

Round 1, on PR #158 at `5beb165`. Each finding is resolved in the follow-up commit, with a case in
`tests/test_detectors.py` `CASES` (also run through the declarative twin) unless noted.

1. **Blocker: a prefixed key name was missed.** The `(?<![A-Za-z0-9_])` edge dropped
   `GOOGLE_CLIENT_SECRET=...` and `AZURE_CLIENT_SECRET="..."`, which the old pattern counted.
   Resolved: the key's left edge excludes letters and digits only, so a name ending in
   `client_secret` or `aws_secret_access_key` counts. Tests for both inputs.
2. **Blocker: quadratic matching.** `_UNQUOTED` held `=` and `_`, so every key inside an
   earlier value's run rescanned it; `"client_secret=" * 14286` took 61 s at `5beb165`.
   Resolved: an unquoted value stops at `=`, which only its padding may end in, so value runs
   are disjoint; the same input now takes about 0.03 s. Timing test added, with an
   `x_client_secret=` variant.
3. **The fake marker and the test path were too wide.** `faker`, `fakeredis`, `FakeResponse`
   and `dummy_request` anywhere in a file switched detection off, and `/tmp/test/` was a test
   path. Resolved: the marker is a whole word (`_` counts as a word character) and must sit on
   the token's own line; a test path is a `tests`, `__tests__`, `testdata`, `fixtures`,
   `__fixtures__` or `__mocks__` folder, Maven's `src/test`, or a test file's own name, and a
   bare `test` or `spec` folder no longer is. Tests: the four look-alikes beside a real token,
   a marker on another line, and `/tmp/test/`. Corpus `4:tu-m7` now marks the value on its own
   line, and the catalog's skip example likewise.
4. **Base32 AWS key ids with no digit were missed** (about 3.6% of real ones). Resolved: the
   AWS key id drops the letters-and-digits rule for a one-repeated-character check; test with
   an all-letter id.
5. **Unquoted secrets with `~` or `.` were missed** (Azure's format). Resolved: `_UNQUOTED`
   takes `~` and `.`; a dotted identifier path is refused as a variable, and the value must end
   at whitespace, a quote, a delimiter or the line's end, an optional sentence-final `.` aside.
   Test with Azure's shape.
6. **A quoted `client_secret` had too weak a placeholder check:** `"my-client-secret"` counted.
   Resolved: the placeholder words take `secret`, `passw` and `token`, a value that names
   itself; test added. `"EXAMPLE-ONLY"` still counts, as recorded under Decisions.
7. **`re.` had no left edge and `mask` alone suppressed a hit.** `store.search(` matched, and
   `echo "::add-mask::ghp_..."` was no hit though it writes the token. Resolved: `re.` needs a
   left edge, and redaction words count only as a call (`redact(`, `mask_token(`). Tests for
   both.

`SECRET_PATTERNS` and `redact` stay unchanged, and the redaction-coverage test still passes over
every positive case, the new ones included.
