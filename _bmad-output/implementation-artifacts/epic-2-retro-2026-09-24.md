### Aggregate views

**Architecture delta.** No module joined the graph. `Detector` gained a keyword-only
`opportunities` slot (`ruleprobe/registry.py`, `dd4d6b6`); `report` now imports the private
`_run` from `registry` (`f40973c`) so `measure()` reuses the context `run()` built. Every edge
points the way AD-1 already allowed; no cycle was introduced. The spine's AD-11 heading was
retagged ADOPTED in `789a499`. Checked by reading the import lines in the three commits; no
dependency tool was run.

- F1. `report` imports a private name, `registry._run`, across modules (`f40973c`). It is the
  cheapest way to share one analysis between hits and opportunities, which AD-11 requires.
  *Instance:* accept. *Prevention:* none.

**Duplication map.**

- F2. The tally invariant (non-negative integer counts) is checked twice: `_tally` validates an
  `opportunities` result when a row is written (`f40973c`), and `_is_tally` validates a stored
  entry when it is read (`789a499`). Their inputs differ, so this is two checks, not one copied.
  *Instance:* accept.
- The fold is not duplicated: `789a499` moved `folded_rules` onto `_folded_items`, the one helper
  `folded_compliance` also reads through, as 2.6 AC7 asked.

**Size growth.**

- F3. `ruleprobe/report.py` went from 308 to 620 lines across the epic (`f40973c` +90,
  `789a499` +222 net) and is 828 lines at `789a499` with Epic 4's `explain` (`ea82257`).
  `report_data` grew from about 121 lines to about 183, and it is the largest function in the
  package. The Epic 1 retrospective asked this one to watch `report.py`. It is not yet a god
  class: the compliance helpers are small, named functions. *Instance:* defer. *Prevention:* the
  Epic 4 retrospective decides whether `explain` or the compliance helpers leave `report.py`.

### Diff-scope review (`bmad-review`: adversarial, edge-case, verification-gap)

`bmad-review` ran the three lenses one after another over the code part of the three commits
(`ruleprobe/` only, about 1,000 diff lines), because this run had no subagents. The boundaries
between stories were weighted: the evaluation memo (2.4) read by `measure()` (2.5), and the
`hook` tag (2.5) read by `report_data` (2.6). Tests, docs and story files were read to confirm
findings, not reviewed as content.

- F8 (edge case; reproduced). `measure()` refuses the output of a compiled `order` detector as
  malformed. The refusal applies when two events that `first` opens on in one turn carry no tool
  use id. `_a_order` builds each point with `_hit(event)`, which gives `tool_use_id` only for a
  `tool_use` event (`ruleprobe/matchers.py`, `dd4d6b6`). A `first` that opens on a `tool_result`,
  an `assistant_text` or a `user_prompt` yields `(turn, None)` once per event. `_tally` refuses a
  repeated `(turn, tool_use_id)` point as `MalformedOpportunities` (`ruleprobe/report.py`,
  `f40973c`; the rule was added in RP-S012's second review), and `tests/test_report.py` lines
  444 to 445 assert that refusal for a hand-written callable. Reproduced on synthetic events: an
  `order` with `first: {kind: tool_result}` over two results in turn 1 gave hits 2,
  `compliance: {}`, and a `rules_errors` entry naming `MalformedOpportunities`. The detector's own
  compiled output reaches the report as a failure; its hits stand. No shipped detector opens on an
  id-less event today. *Instance:* fix now. *Prevention:* see action item 7.
- F9 (verification gap). The AD-11 identity test (`tests/test_opportunities.py`, lines 131 to 163)
  calls `detector.opportunities` directly and never passes the result through `measure()`. A
  compiled detector whose output `measure()` refuses, as in F8, therefore passes it. Its detector
  set (`compiled()`, lines 95 to 108) is `common.yaml`, `docs/rules` and six test-defined
  specs. The shipped catalog, whose `testing/test-after-change` is the first shipped `order`
  detector, is not in that set; `tests/test_catalog.py` checks that detector's triples, not the
  identity. *Instance:* fix now, with F8.
- F10 (adversarial; not reproduced). The evaluation memo is shared mutable state on a compiled
  detector. `evaluated` in `compile_detector` (`ruleprobe/matchers.py`, `dd4d6b6`) writes
  `memo[:] = [events, found]` and then returns `memo[1]`. A second thread that writes between the
  two lines hands the first caller another session's result. Before 2.4, a compiled `fn` held no
  state. The spine plans one session at a time (`ARCHITECTURE-SPINE.md` line 514), so this is no
  breach, but neither the README nor the `Detector` docstring warns a library consumer. Reasoned
  from the code; no concurrent run was made. *Instance:* fix now; replacing the memo atomically as
  a single tuple closes it.
- F11 (adversarial). The memo keeps the last event list alive for the life of the registry. The
  default registry lives as long as the process, so a long-running consumer holds one session's
  events after `report` returns. *Instance:* accept; clearing it can go with F10.
- F12 (adversarial). If an event list is changed in place between `fn` and `opportunities`, the
  second call reads the older evaluation. RP-S011's code review already records this.
  *Instance:* accept.
- F13 (adversarial). A turn-scoped `absent` counts every turn as an opportunity, including turns
  where the rule asked for nothing, because `absent` has no trigger key (AD-7 defers one). Its
  `rate` column therefore measures turns in which the action occurred, not compliance where it
  applied. The matchers docstring says so; the table and README carry no such caveat.
  *Instance:* accept until the trigger key lands. *Prevention:* none beyond the deferral.
- F14 (process, found while tracing). RP-S012 left a question "for the maintainer" in its Design
  section: a raising callable gate stops `run()` and `measure()`. It is not in `deferred-work.md`,
  which holds no Epic 2 entry. *Instance:* fix now; log it. *Prevention:* see action item 6.
- Verification gap, otherwise: **No other verification gaps found.** Checked: positional
  `Detector` construction and the keyword-only slot (`tests/test_registry.py`,
  `tests/test_contract.py`); undecided triples for both kinds (`tests/test_matchers.py`); one
  evaluation per session through `_run` (`ComplianceTests` in `tests/test_report.py`, with the
  mutation checks recorded in RP-S012); the `hook` skip in `errored_detectors`; the minimum,
  grouping, fold and byte-identical `--json` (`tests/test_compliance_report.py`,
  `tests/test_cli.py`).
