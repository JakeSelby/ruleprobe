### Diff-scope review (`bmad-review`: adversarial, edge-case, verification-gap)

`bmad-review` ran the three lenses one after another, because this run had no subagents. They ran
over the code part of the four commits: `ruleprobe/` and `scripts/reference_volume.py`, about
1,400 added lines. The boundaries between stories were weighted: the share (3.3) under section

Tests, docs and story files were read to confirm findings, not reviewed as content.

- F8 (adversarial; reproduced). The README understates the over-count. It says the binding
  over-counts "One place" (line 134): a file with no heading, bound by its whole text. A headed
  section over-counts the same way. With RP-D008's headings-only split, a section of several
  bullet rules is one rule (AD-12), and one catalog-shaped bullet marks the whole section
  measured. Reproduced on a synthetic file whose `## Style` section holds "Keep functions
  short.", "Never force-push to `main`." and "Name things clearly.". The coverage block printed
  `rules: 1 measured, 0 dark, 0 unmeasured (100% measured)`, bound to
  `git-safety/force-push-default`. Two shapes joined in one sentence ("Never skip the pre-commit
  hooks, and never force-push to `main`.") bind the first shape only, because a pattern does not
  reach across a comma. In two sentences, the same pair stays unmeasured as AC3 asks.
  *Instance:* fix now, docs. *Prevention:* none beyond the list-item split that PRD Q2 left out
  of 0.2.
- F9 (adversarial). `testing/test-after-change` binds any sentence that begins "Run the tests …
  before", whatever follows `before`. `tests/test_catalog.py` line 495 asserts that "Run the tests
  before you push." binds. The detector measures something else: each edit followed by a test run
  anywhere later in the session (`within: 100000`, `ruleprobe/detectors/catalog.py` line 102). A
  rule tied to a push or a PR is therefore measured by the "before finishing" proxy. The entry's
  shape is named "Run the tests before finishing". *Instance:* accept, and state it in the entry's
  description. *Prevention:* none.
- F10 (adversarial). `Bundle._bound` keeps every entry each `registry()` call labelled, for the
  life of the bundle (`ruleprobe/rules.py` lines 102 to 105 and 147 to 148). The dictionary grows
  with every call over reassigned rule lists. This is the same shape as Epic 2's F11. *Instance:*
  accept.
- F11 (adversarial; observed). `_short` says a report "never carries somebody's home directory"
  (`ruleprobe/rules.py` line 229). It returns the absolute path for a rule file outside the working
  directory: the probes in Behavior verification printed the scratch directory's full path on
  every section line. The function predates the epic, but section rules print that path once per
  section rather than once per file. The report writes to the terminal only, so nothing leaves
  the machine. *Instance:* defer; correct the docstring or print a `~`-relative path.
- F12 (edge case). `scripts/reference_volume.py` does not check `--recent-share` (line 258). A
  value outside 0 to 1 silently writes an all-recent or all-old volume. `main` checks
  `--sessions`, `--megabytes` and `--subagent-share`. *Instance:* accept; it is maintainer
  tooling, excluded from the sdist.
- F13 (verification gap). Nothing guards NFR-9 after the spike. RP-SP001 measured one path once
  (worst 1.48 s) and filed no follow-up, as its exit criterion allows. The suite's timing tests
  (`HostileInputTests` and `tests/test_order_linear.py`) bound catalog regexes and the `order`
  walk at 5 s over hostile inputs. They never run `report` over a volume. A regression in reading
  or in binding that made the path fifty times slower would fail no check. *Consumer:* SM-1's
  sixty-second test. *Evidence:* searched `tests/` for `reference_volume` and `generate(`. The
  only hits are in `tests/test_reference_volume.py`, which checks bytes, counts and readability,
  not time. *Instance:* defer. *Prevention:* see Open questions.
- Verification gap, otherwise: **No other verification gaps found.** Checked:
  - The share, `<1%` and zero rules (`tests/test_coverage.py` lines 37 to 68 and 109).
  - A catalog-bound rule held out of the printed total (`tests/test_catalog.py` line 829).
